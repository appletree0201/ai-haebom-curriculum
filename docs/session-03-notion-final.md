# 3회차

## 오늘의 목표
- 큰 요청과 작은 요청의 차이를 안다.
- 큰 요청을 바로 실행하지 않고, 먼저 계획으로 나누는 법을 익힌다.
- 플랜모드가 되묻는 질문에 답하면서 요청이 선명해지는 과정을 본다.
- `엑셀 명단 정리` 예시로 입력, 작업, 출력, 확인 기준을 정리한다.

## 먼저 알아둘 말
- 오늘은 엑셀 자동화를 완성하는 날이 아닙니다.
- 오늘은 “AI에게 바로 만들라고 하기 전에, 먼저 계획을 세우는 법”을 배우는 날입니다.

큰 요청은 나쁜 요청이 아닙니다.

다만 큰 요청을 바로 실행하면 결과가 엉뚱해질 수 있습니다.

그래서 3회차에서는 큰 요청을 던진 뒤, 플랜모드로 질문을 되받고, 답하면서 작은 계획으로 바꾸는 흐름을 배웁니다.

## 왜 이걸 배우는가
초보자는 보통 이렇게 요청하고 싶어집니다.

```text
엑셀 명단을 보기 좋게 정리하고 싶어요.
```

이 요청은 자연스럽지만 아직 너무 큽니다.

무엇을 기준으로 정리할지, 어떤 엑셀 파일인지, 어떤 결과를 원하는지, 어떻게 확인할지 알 수 없습니다.

이때 바로 만들라고 하기보다 먼저 이렇게 요청합니다.

```text
바로 실행하지 말고, 먼저 필요한 질문을 해줘.
내 답변을 바탕으로 작은 단계의 계획을 세워줘.
```

이 흐름이 플랜모드의 핵심입니다.

## 큰 요청이란
큰 요청은 범위가 넓고, 결과가 불분명한 요청입니다.

예시는 아래와 같습니다.

```text
엑셀 명단을 보기 좋게 정리하고 싶어요.
```

```text
내 업무를 자동화해줘.
```

```text
이 자료를 정리해줘.
```

큰 요청은 출발점으로는 괜찮습니다.

하지만 바로 실행하기에는 정보가 부족합니다.

## 작은 요청이란
작은 요청은 한 번에 한 가지 일만 시키는 요청입니다.

좋은 작은 요청은 아래 네 가지가 분명합니다.

- 입력: 무엇을 줄 것인가
- 작업: 무엇을 시킬 것인가
- 출력: 어떤 형태로 받을 것인가
- 확인: 무엇을 보면 성공인지

예시입니다.

```text
입력: 엑셀 명단
작업: 부서별 인원 수 세기
출력: 부서별 요약표
확인: 전체 인원 수가 원본과 같은지 비교하기
```

이렇게 작게 만들면 Codex가 무엇을 해야 하는지 분명해집니다.

## 플랜모드란
플랜모드는 바로 실행하기 전에 먼저 계획을 세우는 방식입니다.

초보자는 플랜모드를 이렇게 이해하면 됩니다.

```text
바로 만들지 말고,
먼저 무엇을 확인해야 하는지 질문하고,
그 답을 바탕으로 실행 계획을 세우는 단계
```

중요한 점은 AI가 혼자 모든 걸 맞히는 것이 아닙니다.

AI가 질문을 되묻고, 사람이 답하면서 계획이 선명해집니다.

## 플랜모드가 되묻는 질문 예시
큰 요청:

```text
엑셀 명단을 보기 좋게 정리하고 싶어요.
```

플랜모드의 첫 질문:

```text
현재 이해: 엑셀 명단을 보기 좋게 정리하려는 상황입니다.
막힌 결정: 어떤 기준으로 정리해야 하는지가 아직 불분명합니다.
추천 답안: 먼저 열 이름, 정리 기준, 원하는 결과 형태를 확인하는 것이 좋습니다.
질문: 이 명단에서 가장 먼저 정리하고 싶은 기준은 무엇인가요?
```

답변 예시:

```text
부서별로 나누고 싶어요.
```

플랜모드의 다음 질문:

```text
현재 이해: 엑셀 명단을 부서별로 나누고 싶습니다.
막힌 결정: 결과를 어떤 형태로 받을지가 아직 정해지지 않았습니다.
추천 답안: 초보자 실습에서는 먼저 부서별 인원 수 요약표를 만드는 것이 쉽습니다.
질문: 결과는 부서별 인원 수 요약표로 볼까요, 아니면 부서별 명단을 따로 나눌까요?
```

답변 예시:

```text
일단 부서별 인원 수 요약표가 좋겠습니다.
```

그다음 계획이 만들어집니다.

```text
계획:
1. 엑셀 파일의 열 이름을 확인한다.
2. 부서가 적힌 열을 찾는다.
3. 부서별 인원 수를 센다.
4. 결과를 표로 정리한다.
5. 전체 인원 수가 원본과 맞는지 확인한다.
```

## 요청을 작게 만드는 4칸 공식
플랜모드로 계획을 세울 때 아래 네 칸을 채웁니다.

```text
입력: 무엇을 줄까?
작업: 무엇을 해달라고 할까?
출력: 어떤 모양으로 받을까?
확인: 결과에서 무엇을 볼까?
```

엑셀 명단 정리 예시입니다.

```text
입력: 엑셀 명단 파일
작업: 부서별 인원 수 계산
출력: 부서명 / 인원 수 표
확인: 전체 합계가 원본 명단 인원 수와 같은지 보기
```

이 네 칸이 정리되면 작은 요청으로 바꿀 수 있습니다.

```text
엑셀 명단에서 부서 열을 기준으로 부서별 인원 수를 계산해줘.
결과는 부서명 / 인원 수 표로 보여줘.
마지막에 전체 합계가 원본 인원 수와 맞는지도 확인해줘.
```

## 오늘의 진행 순서
1. 큰 요청 예시를 본다.
2. 왜 바로 실행하기 어려운지 확인한다.
3. 플랜모드로 “바로 실행하지 말고 질문부터 해달라”고 요청한다.
4. 플랜모드가 되묻는 질문에 답한다.
5. 답변을 바탕으로 작은 단계의 계획을 만든다.
6. 계획에서 입력, 작업, 출력, 확인을 확인한다.
7. 그중 첫 번째 작은 요청만 실행 가능한 문장으로 바꿔 본다.
8. 스킬은 나중에 반복 계획 양식으로 묶을 수 있다고 짧게 소개한다.

## 스킬은 어디에 연결되는가
오늘은 스킬을 만드는 날이 아닙니다.

다만 이런 계획 수립 방식이 반복되면 나중에는 스킬로 묶을 수 있습니다.

예를 들어 매번 아래 흐름을 반복한다면:

- 큰 요청을 받는다.
- 필요한 질문을 되묻는다.
- 입력, 작업, 출력, 확인으로 정리한다.
- 작은 실행 계획을 만든다.

이 흐름 자체를 나중에 `계획 수립 스킬`로 만들 수 있습니다.

3회차에서는 스킬 제작보다 “질문을 주고받으며 계획을 세우는 흐름”을 먼저 익힙니다.

## 자주 막히는 지점
- 큰 요청을 바로 실행하려는 경우
- AI가 질문하는 것을 귀찮게 느끼는 경우
- 답변을 대충 해서 계획이 흐려지는 경우
- 결과 형태를 정하지 않는 경우
- 확인 기준 없이 바로 만들려고 하는 경우

## 집에서 할 일
- 내 업무에서 큰 요청 하나를 적어 본다.
- 그 요청을 Codex에게 바로 실행시키지 않는다.
- 먼저 필요한 질문을 해달라고 요청한다.
- 질문에 답하면서 계획을 세워 본다.
- 계획 중 첫 번째 작은 요청만 실행 가능한 문장으로 바꿔 본다.

## 다음 회차 예고
다음 회차에서는 실제 업무자동화 구현 사례를 봅니다.

홈페이지에 들어오는 질문을 자동으로 분류하고, 답변 초안을 만드는 작업본을 확인합니다.

3회차에서 배운 플랜모드 흐름이 실제 업무자동화를 작은 단계로 나누는 데 어떻게 연결되는지 봅니다.

## 마무리
3회차의 핵심은 하나입니다.

큰 요청을 바로 실행하지 말고, 플랜모드로 질문을 되받아 계획을 세우는 것입니다.

계획이 작아져야 실행도 쉬워집니다.
