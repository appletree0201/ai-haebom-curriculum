# 1회차 

## 오늘의 목표
- `VS Code` 설치와 기본 화면을 확인한다.
- `Codex`를 연결한다.
- 로그인과 권한을 확인한다.
- 샘플 실행까지 경험한다.
- `AGENTS.md`, `skills.md`, `세션`은 다음 회차에 자세히 다룰 개념이라는 점만 안다.
- 작은 요청을 보내고 결과를 확인하는 바이브 코딩 흐름을 익힌다.

## 먼저 알아둘 말
처음 접하면 아래 단어들이 낯설 수 있습니다.

- `VS Code`는 코드를 쓰는 프로그램입니다.
- `Codex`는 AI에게 작업을 요청하는 도구입니다.
- `AGENTS.md`와 `skills.md`는 다음 회차에서 본격적으로 다룰 문서와 개념입니다.
- `세션`은 지금까지의 작업 흐름을 이어가는 상태라고 생각하면 됩니다.

오늘은 이 단어들을 완전히 외우는 날이 아닙니다.

어떤 역할을 하는지 감만 잡으면 충분합니다.

## 함께 볼 자료
1회차는 설명자료만으로 끝내지 않습니다.

집에서 실습할 때는 아래 두 자료를 함께 봅니다.

- `1회차 설치 체크리스트`: 설치와 설정을 순서대로 확인하는 자료
- `1회차 문제 해결 FAQ`: 막혔을 때 증상별로 확인하는 자료

현장에서는 설치를 끝까지 같이 하지 않고, 흐름과 확인 지점을 보여줍니다.

실제 설치와 샘플 실행은 집에서 체크리스트를 보며 각자 진행합니다.

## 오늘 다룰 내용
- 왜 업무자동화가 필요한가
- `VS Code`가 무엇인가
- `VS Code`를 어디에서 다운로드하는가
- `VS Code`를 한글로 어떻게 바꾸는가
- 필요한 확장 프로그램을 어떻게 설치하는가
- `Codex`가 무엇인가
- `AGENTS.md`와 `skills.md`는 다음 회차에서 어떻게 다루는가
- 세션이 무엇인가
- 설치와 연결을 어떻게 확인하는가
- 샘플 실행은 어떻게 하는가
- 집에서 무엇을 다시 해보면 되는가

## 왜 이걸 배우는가
반복되는 업무는 생각보다 많습니다.

문서 정리, 파일 정리, 복사와 붙여넣기, 양식 맞추기, 결과 비교 같은 작업은 시간이 많이 들고 실수도 생기기 쉽습니다.

이런 일은 Python 기반 자동화와 AI 도구를 함께 쓰면 점차 줄일 수 있습니다.

이번 회차는 그 시작점입니다.

예를 들어, 같은 이름의 파일이 여러 개 있거나, 같은 문장을 계속 고쳐 써야 하거나, 비슷한 자료를 여러 번 정리해야 하는 일이 있습니다.

이런 작업은 사람이 직접 하면 지루하고 실수하기 쉽습니다.

AI와 코드를 같이 쓰면, 이런 반복을 조금씩 줄일 수 있습니다.

## 핵심 개념

### VS Code
코드를 작성하고 실행하는 작업 공간입니다.

초보자에게는 파일을 열고, 수정하고, 저장하고, 실행하는 기본 도구라고 보면 됩니다.

처음에는 메모장처럼 보일 수 있지만, 실제로는 코드와 폴더를 다루는 작업실에 가깝습니다.

여기서 파일을 열고, 수정하고, 저장하고, 결과를 확인합니다.

### Codex
자연어 요청을 바탕으로 파일 작업과 코드 작업을 도와주는 AI 도구입니다.

질문만 하는 도구가 아니라, 실제 작업 흐름을 함께 만드는 보조 도구입니다.

쉽게 말하면, "이 작업을 이렇게 해줘"라고 말하면 초안을 만들고 수정까지 도와주는 도구입니다.

하지만 그냥 알아서 다 해주는 도구는 아닙니다.

무엇을 원하는지 작게, 분명하게 말해야 잘 동작합니다.

### AGENTS.md와 skills.md
이름만 먼저 익혀 둡니다.

`AGENTS.md`는 작업 규칙을 담는 문서이고, `skills.md`는 반복 작업의 절차를 담는 문서입니다.

오늘은 이 두 문서가 있다는 것만 알면 충분합니다.

자세한 내용은 2회차에서 직접 다룹니다.

### 세션
지금까지의 작업 상태와 맥락을 이어가는 단위입니다.

이전 작업을 알아야 다음 작업이 자연스럽게 이어집니다.

세션이 이어진다는 것은, 내가 방금 무엇을 했는지 AI가 기억하고 다음 요청을 이어받는다는 뜻입니다.

그래서 너무 큰 작업을 한 번에 하기보다, 조금씩 이어가는 방식이 좋습니다.

## 오늘의 진행 순서
1. `VS Code` 공식 다운로드 위치를 확인합니다.
2. 설치 파일을 실행하고 기본 설치 흐름을 이해합니다.
3. `VS Code`를 열고 기본 화면을 익힙니다.
4. 한글 언어팩을 설치하는 방법을 봅니다.
5. 필요한 확장 프로그램을 설치하는 방법을 봅니다.
6. 작업할 폴더를 엽니다.
7. `Codex`를 연결합니다.
8. 로그인 상태와 권한을 확인합니다.
9. 짧은 샘플을 실행합니다.
10. 결과를 확인하고 저장 위치를 이해합니다.

## VS Code 다운로드와 설치
`VS Code`는 공식 사이트에서 다운로드합니다.

- 주소: `https://code.visualstudio.com/`
- Windows 사용자는 `Download for Windows` 버튼을 누릅니다.
- 설치 파일을 다운로드한 뒤 실행합니다.
- 처음에는 특별한 이유가 없으면 기본값으로 설치를 진행합니다.
- 설치가 끝나면 시작 메뉴나 바탕화면에서 `Visual Studio Code`를 실행합니다.

### 설치할 때 기억할 점
- 비슷한 이름의 다른 사이트가 아니라 공식 사이트에서 받습니다.
- 설치 중 어려운 선택지가 나오면 기본값을 유지해도 됩니다.
- 설치 후 프로그램이 열리면 1단계는 성공입니다.

## VS Code를 한글로 바꾸기
처음 설치하면 메뉴가 영어로 보일 수 있습니다.

영어 화면이 불편하면 한글 언어팩을 설치합니다.

1. 왼쪽 사이드바에서 `Extensions` 아이콘을 누릅니다.
2. 검색창에 `Korean Language Pack`을 입력합니다.
3. `Korean Language Pack for Visual Studio Code`를 찾습니다.
4. `Install` 버튼을 누릅니다.
5. 설치 후 다시 시작하라는 안내가 나오면 `Restart`를 누릅니다.
6. 다시 열린 뒤 메뉴가 한글로 보이는지 확인합니다.

### 한글 설정에서 막히면 볼 것
- 검색어를 정확히 `Korean Language Pack`으로 입력했는지 봅니다.
- 설치 버튼이 `Install`에서 `Uninstall` 또는 `Disable`로 바뀌었는지 봅니다.
- 설치 후 재시작을 했는지 봅니다.

## 확장 프로그램 설치 방법
확장 프로그램은 `VS Code`에 기능을 추가하는 작은 도구입니다.

초보자는 설치 위치부터 알아야 합니다.

1. 왼쪽 사이드바에서 `Extensions` 아이콘을 누릅니다.
2. 검색창에 필요한 확장 프로그램 이름을 입력합니다.
3. 검색 결과에서 이름과 제공자를 확인합니다.
4. `Install` 버튼을 누릅니다.
5. 설치 후 버튼이 `Uninstall` 또는 `Disable`로 바뀌면 설치된 것입니다.

### 1회차 권장 확장
- `Korean Language Pack for Visual Studio Code`
- `Python`
- `Codex` 또는 `OpenAI Codex`
- `Excel Viewer` 또는 엑셀/CSV 미리보기 확장
- 필요 시 `Markdown All in One`

### 엑셀 뷰어 확장은 왜 설치하나
엑셀 뷰어 확장은 향후 엑셀이나 CSV 자료를 확인하기 위한 사전 준비입니다.

1회차에서는 엑셀 자료 처리를 직접 다루지 않습니다.

다만 나중에 엑셀 파일이나 CSV 파일을 `VS Code` 안에서 확인할 수 있도록 미리 설치 위치를 익혀 둡니다.

### Codex 확장 설치 시 주의할 점
Codex 확장 이름은 버전이나 환경에 따라 다르게 보일 수 있습니다.

검색 결과가 여러 개라면 임의로 설치하지 말고, `AI 해봄` 안내 화면과 이름 및 제공자를 비교합니다.

자료에는 특정 화면이 항상 똑같이 나온다고 가정하지 않습니다.

그래서 1회차에서는 "Codex 확장을 찾는 위치와 확인 방법"을 먼저 익힙니다.

## 환경 세팅 확인 항목
- `VS Code`가 설치되어 있는가
- 실행이 되는가
- 한글 언어팩이 필요한 경우 설치했는가
- 필요한 확장 프로그램을 설치할 수 있는가
- 엑셀/CSV 보기용 확장을 설치했는가
- 기본 폴더를 열 수 있는가
- `Codex`를 연결할 수 있는가
- 로그인은 완료되었는가
- 권한 문제가 없는가

### 왜 이 항목들을 확인하나
- 설치 여부를 확인하는 이유는, 프로그램이 아예 열리지 않으면 다음 단계로 갈 수 없기 때문입니다.
- 폴더를 열어야 하는 이유는, Codex가 어디를 바꿔야 하는지 알아야 하기 때문입니다.
- 로그인과 권한을 확인하는 이유는, 도구가 막히는 가장 흔한 이유가 여기에 있기 때문입니다.

## 권한 화면 설명
실제 Codex 화면에서는 권한을 다음처럼 볼 수 있습니다.

- `기본 권한`
- `전체 액세스`
- `맞춤형(config.toml)`

### 각 항목을 쉽게 설명하면
- `기본 권한`: 보통의 안전한 기본 상태입니다.
- `전체 액세스`: 더 많은 작업을 허용하는 상태입니다.
- `맞춤형(config.toml)`: 설정 파일로 세부 권한을 조정하는 방식입니다.

### 초보자가 기억할 점
- 처음에는 보통 `기본 권한`부터 확인합니다.
- `전체 액세스`는 더 많은 일을 할 수 있지만, 초보자에게는 의미를 먼저 이해해야 합니다.
- `맞춤형(config.toml)`은 바로 쓰는 기능이라기보다, 나중에 세부 설정을 조정할 때 참고하는 방식입니다.
- 화면 표기는 버전이나 환경에 따라 조금 다를 수 있습니다.

## 화면에서 볼 것
처음 보는 사람은 "어디를 봐야 하는지"가 더 중요합니다.

다음 네 가지를 눈여겨 봅니다.

- 왼쪽의 파일 목록
- 가운데의 편집 화면
- 아래쪽의 실행 결과나 메시지
- Codex가 응답하는 위치

이 네 곳이 오늘 가장 중요합니다.

## 시연할 때 보여줄 것
현장에서는 아래 흐름을 직접 보여줍니다.

1. `VS Code` 공식 다운로드 사이트 확인
2. 설치 파일과 실행 위치 확인
3. `VS Code` 실행
4. 한글 언어팩 설치 위치 확인
5. 확장 프로그램 설치 위치 확인
6. 작업 폴더 열기
7. `Codex` 연결
8. 간단한 요청 보내기
9. 응답 확인
10. 결과가 어디에 반영되는지 확인

이 과정의 핵심은 결과를 보는 데 있습니다.

초보자는 "요청했다"에서 끝내기 쉽습니다.

하지만 실제로는 "어디에 무엇이 바뀌었는지"까지 확인해야 합니다.

예를 들어, 파일 이름이 바뀌었는지, 문장이 수정되었는지, 새 파일이 생겼는지, 저장 위치가 어디인지까지 확인해야 합니다.

이 확인이 없으면, 나중에 무엇이 잘 됐는지 알 수 없습니다.

### 샘플 요청 예시
처음 보여줄 샘플은 두 종류로 나누는 것이 좋습니다.

#### 1. 일반 챗GPT로도 가능한 예시
- `이 메일 답장 초안을 좀 더 공손하게 써줘.`
- `이 공지문을 더 짧고 읽기 쉽게 바꿔줘.`
- `이 업무 설명을 초보자도 이해할 수 있게 바꿔줘.`

이런 예시는 AI 대화 연습에는 좋지만, Codex의 강점을 크게 보여주지는 못합니다.

#### 2. Codex 시연에 더 맞는 예시
- `현재 작업 폴더에 YYYY-MM-DD 형식의 md 파일을 만들고, 오늘 배운 내용을 3개 항목으로 정리해줘.`
- `현재 작업 폴더에 today-note.md 파일을 만들고, 오늘 확인한 내용과 내일 할 일을 구분해서 적어줘.`
- `현재 작업 폴더에 회의후속조치.md 파일을 만들고, 오늘 나온 할 일 3개를 정리해줘.`
- `현재 작업 폴더에 환경세팅기록.md 파일을 만들고, 오늘 확인한 설정과 막힌 점을 정리해줘.`

이런 예시는 실제 파일을 바꾸기 때문에 Codex의 역할이 더 분명하게 보입니다.

### 왜 이 구분이 필요한가
- 일반 문장 수정은 ChatGPT로도 충분히 할 수 있습니다.
- Codex는 작업공간 안의 파일을 보고, 수정하고, 결과를 남기는 데 강점이 있습니다.
- 그래서 1회차 시연에서는 "대화"보다 "파일 작업"이 더 잘 맞습니다.

### 시연할 때 실제로 확인할 것
- 새 파일이 생겼는가
- 기존 파일이 실제로 수정되었는가
- 어디가 바뀌었는지 바로 찾을 수 있는가
- 수정 결과가 작업 폴더 안에 남았는가

## 자주 막히는 지점
- 어디에서 다운로드해야 하는지 모르는 경우
- 영어 화면에서 메뉴를 찾지 못하는 경우
- 확장 프로그램 검색 결과가 여러 개라서 헷갈리는 경우
- 설치는 되었는데 실행이 안 되는 경우
- 로그인은 되었는데 권한이 없는 경우
- 어느 폴더에서 작업해야 하는지 모르는 경우
- 요청을 너무 크게 보내서 결과가 흐려지는 경우
- 결과를 확인하지 않고 다음 단계로 넘어가는 경우

### 막히면 먼저 볼 것
1. 공식 다운로드 사이트에서 설치했는지 본다.
2. 프로그램이 열리는지 본다.
3. 한글 언어팩이 필요한 경우 설치했는지 본다.
4. 확장 프로그램이 설치되었는지 본다.
5. 작업 폴더가 맞는지 본다.

7. 권한 관련 메시지를 본다.
8. 요청이 너무 길지 않은지 본다.

## 오늘의 메시지
오늘은 복잡한 자동화를 만드는 날이 아닙니다.

오늘은 도구를 연결하고, 기본 개념을 이해하고, 다음 실습을 할 수 있는 바탕을 만드는 날입니다.

즉, "도구를 처음 만지는 날"이 아니라 "이후 실습이 가능해지는 날"입니다.

작게 요청하고, 바로 결과를 보고, 필요한 부분만 고치는 방식이 앞으로의 기본 패턴입니다.

처음부터 잘할 필요는 없습니다.

다만, 실패했을 때 어디를 다시 보면 되는지는 알아야 합니다.
