# 10회차

## 오늘의 주제
오늘은 `업무자동화 시작점 공유회`입니다.

10회차는 끝맺음 발표가 아닙니다.

지금까지 배운 도구와 방법을 바탕으로, 각자 또는 각 부서의 업무자동화가 앞으로 어떻게 자라날 수 있는지 공유하는 시간입니다.

```text
10회차는 끝이 아닙니다.
지금까지는 준비 과정이었습니다.
이제부터 각자의 업무자동화가 실제 업무 안에서 시작됩니다.
```

## 오늘의 목표
- 각 과제의 현재 상태를 부담 없이 공유한다.
- 완성 여부보다 배운 점과 가능성을 나눈다.
- 실제로 써 보며 느낀 점을 말한다.
- 막힌 점과 위험한 점을 숨기지 않고 공유한다.
- 발표 후 아이디어 확장 질문으로 앞으로의 방향을 넓힌다.
- 10회차 이후에도 동호회 활동이 계속 이어진다는 점을 확인한다.

## 오늘은 끝이 아니라 시작이다
10회차라는 숫자 때문에 마무리처럼 느껴질 수 있습니다.

하지만 이 모임의 목표는 10회 안에 모든 자동화를 완성하는 것이 아닙니다.

1~10회차는 아래를 준비하는 과정이었습니다.

- VS Code와 Codex 사용에 익숙해지기
- AGENTS.md와 skills 개념 이해하기
- 큰 요청을 작은 요청으로 나누기
- 업무자동화 후보 찾기
- Markdown과 Git으로 기록 남기기
- 자료를 LLM Wiki처럼 쌓아 보기
- 진행 중인 과제를 공유하고 도움 요청하기
- 최신 AI 흐름을 업무 관점에서 바라보기

이제부터는 각자의 실제 업무 안에서 작게 써 보고, 고치고, 다시 요청하고, 동료와 나누는 단계입니다.

## 오늘은 평가 시간이 아니다
오늘은 잘한 과제와 못한 과제를 나누는 시간이 아닙니다.

완성된 프로그램이 없어도 괜찮습니다.

아래 중 하나만 있어도 공유할 수 있습니다.

- 아이디어만 있는 과제
- 입력 자료만 정한 과제
- 출력 결과 모양만 정한 과제
- Codex에게 요청해 본 과제
- 일부라도 실행되는 과제
- 아직 막혀서 멈춘 과제

중요한 것은 현재 상태를 꺼내 놓고, 앞으로 어떻게 키울 수 있을지 같이 보는 것입니다.

## 공유 항목 5가지
각 과제는 아래 5가지만 짧게 공유합니다.

```text
1. 과제 이름
2. 현재 결과물 또는 진행 상태
3. 실제로 써 보니 좋았던 점
4. 막힌 점 또는 위험한 점
5. 느낀 점
```

`다음 개선 행동`을 구체적으로 확정하지 않아도 됩니다.

동호회 활동은 10회차에서 끝나지 않기 때문입니다.

오늘은 앞으로 키워 갈 방향과 가능성을 넓히는 데 집중합니다.

## 좋은 시작점 공유 예시
아래처럼 말하면 부담 없이 공유하면서도 같이 이야기할 지점이 분명해집니다.

```text
과제 이름: 교육 문의 답변 초안 정리
현재 결과물 또는 진행 상태: 문의 문장을 넣으면 분류와 답변 초안이 나오는 형태까지 해 봤습니다.
실제로 써 보니 좋았던 점: 반복해서 쓰는 안내 문장을 빨리 만들 수 있었습니다.
막힌 점 또는 위험한 점: 답변이 너무 확정적으로 나와서 담당자 확인이 꼭 필요합니다.
느낀 점: AI가 답을 대신한다기보다 초안을 빨리 만들어 주는 도구라는 느낌을 받았습니다.
```

좋은 점:
- 완성 여부보다 현재 상태가 보인다.
- 실제로 써 본 느낌이 들어 있다.
- 위험한 점을 숨기지 않는다.
- 앞으로 더 키울 방향을 이야기할 수 있다.

## 아이디어 확장 질문이란
아이디어 확장 질문은 과제를 평가하기 위한 질문이 아닙니다.

과제를 더 넓게 보거나, 더 작게 줄이거나, 다른 업무로 옮겨 볼 수 있는지 생각하게 하는 질문입니다.

```text
아이디어 확장 질문 = 지금 과제를 앞으로 어떻게 키울 수 있을지 여는 질문
```

정답을 바로 내기 위한 질문이 아닙니다.

서로의 과제를 보며 “이런 방향도 가능하겠다”는 관점을 얻기 위한 질문입니다.

## 아이디어 확장 질문 예시
발표 후 아래 질문 중 2~3개를 골라 이야기합니다.

```text
이 과제를 다른 부서에서도 쓸 수 있을까요?
```

```text
입력 자료를 바꾸면 다른 업무에도 적용될까요?
```

```text
사람이 확인해야 하는 부분은 어디까지 남겨야 할까요?
```

```text
이 과제를 더 작게 만들면 무엇부터 할 수 있을까요?
```

```text
나중에 다른 시스템과 연결한다면 어디가 좋을까요?
```

```text
이 과제에서 반드시 사람이 판단해야 하는 부분은 무엇일까요?
```

## 공통 인사이트 정리하기
여러 과제를 듣다 보면 비슷한 배움이 반복됩니다.

예시는 아래와 같습니다.

- 입력 자료가 정리되어야 자동화가 쉬워진다.
- 결과물 모양을 먼저 정하면 Codex에게 요청하기 쉽다.
- 사람의 확인이 필요한 부분은 남겨야 한다.
- 처음부터 큰 자동화를 만들려고 하면 막힌다.
- 작은 자동화라도 실제 업무 흐름에 들어가야 의미가 있다.
- 보안과 내부자료 주의사항은 계속 확인해야 한다.

10회차에서는 이런 공통 인사이트를 함께 모읍니다.

## 오늘의 진행 순서
1. 10회차가 끝이 아니라 시작점이라는 것을 확인한다.
2. 공유 항목 5가지를 설명한다.
3. 과제별로 현재 상태와 느낀 점을 짧게 공유한다.
4. 발표 후 아이디어 확장 질문을 던진다.
5. 여러 과제에서 반복되는 공통 인사이트를 정리한다.
6. 10회 이후 동호회 활동으로 어떻게 이어갈지 이야기한다.

## 1시간 운영안
```text
0~5분: 10회차 목적 설명
5~10분: 공유 항목 5가지 설명
10~35분: 과제별 시작점 공유
35~50분: 아이디어 확장 질문
50~57분: 공통 인사이트 정리
57~60분: 이제부터 시작 메시지
```

## 10회 이후 이어갈 방향
10회차 이후에는 완성 여부보다 아래 흐름을 이어갑니다.

```text
작게 써 보기
-> 결과 확인하기
-> 다시 요청하기
-> 동료와 나누기
-> 실제 업무 흐름에 맞게 고치기
```

동호회는 도구 사용법을 배우는 모임에서 끝나지 않습니다.

각자의 업무 안에서 실제로 쓸 수 있는 자동화를 함께 키워 가는 모임으로 이어집니다.

## 이제부터 시작
오늘 공유한 과제는 완성품이 아닙니다.

각자의 업무 안에서 계속 자라날 시작점입니다.

10회차는 끝이 아니라, 업무자동화를 실제 업무 속에서 키워 가는 출발선입니다.
