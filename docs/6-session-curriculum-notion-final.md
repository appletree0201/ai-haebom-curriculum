# 1~6회 전체 커리큘럼

## 문서 목적
이 문서는 사내 AI 동호회의 1회부터 6회까지 전체 흐름을 정리한 커리큘럼입니다.

대상은 비전공자와 초보자입니다.

운영 방식은 매회 1시간 모임 후, 각자 자료를 보고 집에서 다시 실습하는 구조입니다.

## 전체 목표
6회가 끝날 때에는 참가자가 다음 상태에 도달해야 합니다.

- `VS Code`와 `Codex`를 기본적으로 사용할 수 있다.
- `AGENTS.md`, `skills.md`, `세션`의 의미를 안다.
- 자동화 과제를 카드 형태로 정리할 수 있다.
- Git으로 작업 기록을 남기는 기본 흐름을 이해한다.
- 자신의 업무에서 작은 자동화 과제를 하나 이상 도출할 수 있다.
- 바이브 코딩 방식으로 작은 구현을 시도할 수 있다.

## 운영 방식
- 매회 1시간으로 진행한다.
- 현장에서는 시연, 설명, 질문 답변, 토론을 중심으로 한다.
- 이후 참가자는 배부 자료를 보고 혼자 다시 실습한다.
- 각 회차는 `작게 요청 -> 결과 확인 -> 조금 수정`의 흐름을 포함한다.

## 회차별 흐름

### 1회차: 시작하기
- `VS Code` 공식 다운로드 위치와 설치 흐름을 확인한다.
- 한글 언어팩과 기본 확장 프로그램 설치 방법을 익힌다.
- 향후 엑셀이나 CSV 자료 확인을 위해 엑셀/CSV 보기용 확장 설치 위치도 확인한다.
- `VS Code` 기본 화면과 폴더 여는 방법을 확인한다.
- `Codex` 연결, 로그인, 권한 확인, 샘플 실행을 경험한다.
- 설치 체크리스트와 문제 해결 FAQ를 보고 집에서 각자 실습한다.
- `AGENTS.md`, `skills.md`, `세션`은 이름과 역할만 먼저 익힌다.
- `ai-haebom-practice.md` 실습 메모 양식을 만들고, 파일 생성 결과를 확인하는 샘플을 경험한다.
- 목표는 처음 설치부터 기본 설정과 연결 흐름까지 이해하는 것이다.

### 2회차: Codex로 작은 작업하기
- `AGENTS.md`가 무엇인지, 왜 먼저 읽는지, 어떤 순서로 적용되는지 배운다.
- 우리 작업공간의 루트/하위 `AGENTS.md`를 비교해 본다.
- `AGENTS.md`는 자동 생성이 아니라 사람이 직접 쓰는 문서라는 점을 이해한다.
- `AGENTS.md`에 들어갈 한 줄 규칙을 직접 써보는 맛보기 실습을 한다.
- `skills`가 무엇인지, 언제 쓰는지, 왜 반복 작업에 도움이 되는지 익힌다.
- 사진과 재미용 학습 키워드로 같은 스케치 노트 스타일의 카드를 만드는 예시를 통해 skill의 반복성을 눈으로 확인한다.
- 작은 수정과 반복 요청을 통해 바이브 코딩의 기본 루프를 익힌다.

### 3회차: 플랜모드로 큰 요청을 작은 계획으로 나누기
- 큰 요청을 바로 실행하지 않고 먼저 계획으로 나누는 흐름을 익힌다.
- 플랜모드가 되묻는 질문에 답하면서 요구사항이 선명해지는 과정을 본다.
- `엑셀 명단을 보기 좋게 정리하고 싶어요` 같은 큰 요청을 입력, 작업, 출력, 확인 기준으로 나눠 본다.
- 계획 중 첫 번째 단계만 실행 가능한 작은 요청으로 바꾸는 연습을 한다.
- 스킬 만들기는 본격적으로 다루지 않고, 반복되는 계획 수립 방식은 나중에 스킬로 묶을 수 있다고 소개한다.

### 4회차: 실제 업무자동화 구현 사례 보기
- AI 해봄에서 실제로 만들고 있는 업무자동화 작업본을 본다.
- 사례는 홈페이지 문의를 자동으로 분류하고 답변 초안을 생성하는 흐름이다.
- 회원 각자의 제작물을 발표하는 시간이 아니라, 실제 구현 과정을 보고 인사이트를 얻는 시간이다.
- `문의 입력 -> 유형 분류 -> 답변 초안 -> 담당자 확인` 흐름을 이해한다.
- AI가 확정 답변을 하는 것이 아니라 담당자가 검토할 초안을 만든다는 경계를 배운다.
- 3회차에서 배운 플랜모드가 실제 자동화 구현 단계로 어떻게 이어지는지 확인한다.

### 5회차: 각 부서별 자동화 과제 정의 + Markdown
- 4회차 이후 각 부서에서 생각해 온 자동화 후보를 공유한다.
- Markdown 아주 기초 문법을 10분 정도 익힌다.
- 후보 중 하나를 골라 `부서별 자동화 과제 카드`로 정리한다.
- 입력, 작업, 출력, 확인 기준을 채운다.
- 사람이 반드시 확인해야 할 부분과 첫 구현 범위를 정한다.
- 이 카드는 이후 첫 구현 요청과 10회차 중간 공유 자료의 기준이 된다.

### 6회차: Windows Git 설치와 기본 기록 남기기
- Git을 작업 기록을 남기는 도구로 이해한다.
- Windows에서 Git을 설치하고 설치 여부를 확인한다.
- VS Code 터미널에서 `git init`, `git status`, `git add`, `git commit`을 실행한다.
- `git-practice.md` 파일을 만들어 별도 실습으로 진행한다.
- 스테이징과 커밋의 차이를 이해한다.
- GitHub, branch, merge, conflict는 다루지 않는다.

## 6회 종료 시점의 도달 상태
6회가 끝날 때에는 아래가 가능해야 합니다.

- 반복 업무를 자동화 과제로 바꿔 설명할 수 있다.
- 작업을 아주 작은 단위로 나눌 수 있다.
- Markdown으로 부서별 자동화 과제 카드를 작성할 수 있다.
- Git을 설치하고 로컬 작업 기록을 남기는 기본 흐름을 이해한다.
- `init`, `status`, `add`, `commit`의 역할을 구분할 수 있다.
- 이후 구현을 시작할 준비 자료를 갖춘다.

## 공통 과제
매 회차마다 참가자는 다음을 하게 됩니다.

- 오늘 배운 내용을 집에서 다시 따라 해 본다.
- 자신의 업무에서 비슷한 반복 작업을 찾아본다.
- 다음 회차에서 물어볼 질문을 적어 둔다.
- 막힌 지점을 메모해 둔다.

## 마무리
이 커리큘럼의 목표는 지식 전달로 끝나지 않는 것입니다.

최종적으로는 각자 작은 자동화 과제를 하나 이상 꺼내고, 이제부터 만들어 나갈 준비가 된 상태를 만드는 것입니다.

그 준비의 핵심은 `도구를 아는 것`, `작게 요청하는 것`, `결과를 확인하는 것`, `조금씩 고치는 것`입니다.
