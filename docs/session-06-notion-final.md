# 6회차

## 오늘의 목표
- Git이 변경 기록을 남기는 도구라는 점을 이해한다.
- Windows에서 Git 설치 흐름을 안다.
- `init`, `status`, `add`, `commit`의 역할을 구분한다.
- 작은 파일 하나를 기록으로 남기는 흐름을 이해한다.

## 먼저 알아둘 말
오늘은 GitHub를 배우는 날이 아닙니다.

오늘은 내 컴퓨터 안에서 변경 기록을 남기는 기본 흐름만 봅니다.

브랜치, 머지, 충돌, 푸시, 풀은 다루지 않습니다.

## 왜 Git을 배우는가
자동화 자료와 코드는 계속 바뀝니다.

무엇을 언제 바꿨는지 기록하지 않으면 나중에 되돌아보기 어렵습니다.

Git은 파일 변경을 단계별로 기록하는 도구입니다.

초보자는 처음에 네 가지 명령만 기억하면 됩니다.

```text
git init
git status
git add
git commit
```

## 핵심 개념
### 저장소
Git이 변경 기록을 관리하는 폴더입니다.

### 상태 확인
`git status`는 지금 어떤 파일이 바뀌었는지 보여줍니다.

### 스테이징
`git add`는 이번 기록에 포함할 파일을 고르는 단계입니다.

### 커밋
`git commit`은 선택한 변경사항을 하나의 기록으로 남기는 단계입니다.

## 기본 흐름
1. 실습 폴더를 엽니다.
2. Git 저장소로 초기화합니다.
3. 파일을 하나 만듭니다.
4. 상태를 확인합니다.
5. 기록할 파일을 선택합니다.
6. 커밋 메시지와 함께 기록합니다.

## 함께 확인할 포인트
- Git은 백업 도구가 아니라 변경 기록 도구입니다.
- `status`를 자주 확인하면 현재 상태를 이해하기 쉽습니다.
- `add`는 기록할 대상을 고르는 단계입니다.
- `commit`은 기록을 남기는 단계입니다.
- 처음에는 명령어를 많이 외우지 않아도 됩니다.

## 각자 해보기
- Windows에 Git이 설치되어 있는지 확인합니다.
- VS Code에서 실습 폴더를 엽니다.
- 터미널을 열고 `git init`을 실행합니다.
- `git-practice.md` 파일을 만듭니다.
- `git status`로 상태를 확인합니다.
- `git add git-practice.md`를 실행합니다.
- `git commit -m "첫 Git 연습 기록"`으로 기록을 남깁니다.
