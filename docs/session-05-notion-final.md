# 5회차

## 오늘의 목표
- 자동화 과제를 작게 정의하는 법을 이해한다.
- Markdown이 무엇이고 왜 자동화 과제 정리에 도움이 되는지 안다.
- VS Code에서 Markdown 파일을 만들고 미리보는 흐름을 이해한다.
- 부서별 자동화 과제 카드를 작성할 준비를 한다.

## 먼저 알아둘 말
오늘은 자동화를 구현하는 날이 아닙니다.

무엇을 자동화할지 정리하는 날입니다.

자동화는 과제가 흐릿하면 시작하기 어렵습니다.

먼저 입력, 반복 작업, 결과물, 확인 기준을 적어야 합니다.

## 왜 Markdown을 쓰는가
Markdown은 글을 구조적으로 적는 간단한 문서 형식입니다.

제목, 목록, 표, 코드 조각을 쉽게 쓸 수 있습니다.

사람도 읽기 쉽고 Codex도 이해하기 쉬워서 자동화 과제 정리에 적합합니다.

## 핵심 개념 1: 자동화 과제 카드
자동화 과제 카드는 “무엇을 자동화할지”를 한 장으로 정리하는 문서입니다.

아래 항목을 포함하면 좋습니다.

- 업무 이름
- 현재 반복되는 일
- 입력 자료
- 원하는 결과물
- 사람이 확인해야 할 기준
- 막히는 지점
- 도움받고 싶은 부분

## 핵심 개념 2: 작게 정의하기
처음부터 큰 자동화를 만들려고 하면 어렵습니다.

예를 들어 “부서 업무를 자동화하고 싶다”는 너무 큽니다.

아래처럼 작게 바꿔야 시작할 수 있습니다.

```text
매주 받는 엑셀 명단에서 직급별 인원을 계산해 md 요약표로 만들고 싶다.
```

작게 정의하면 Codex에게 요청하기 쉽고, 결과도 확인하기 쉽습니다.

## 핵심 개념 3: VS Code에서 Markdown 작성
Markdown은 VS Code에서 작성할 수 있습니다.

파일 이름은 보통 `.md`로 끝납니다.

예시는 아래와 같습니다.

```text
department-automation-card.md
```

VS Code에서는 Markdown 미리보기를 열어 제목과 목록이 어떻게 보이는지 확인할 수 있습니다.

## 함께 확인할 포인트
- 자동화 과제는 작게 시작합니다.
- 입력 자료와 결과물이 분명해야 합니다.
- 사람이 확인할 기준을 반드시 적습니다.
- Markdown은 자동화 과제를 정리하기 위한 가벼운 문서 형식입니다.
- 오늘 만든 카드는 이후 구현과 공유의 기준이 됩니다.

## 각자 해보기
- VS Code에서 실습 폴더를 엽니다.
- `department-automation-card.md` 파일을 만듭니다.
- 업무 이름과 반복되는 일을 적습니다.
- 입력 자료와 원하는 결과물을 적습니다.
- 사람이 확인해야 할 기준을 적습니다.
- Markdown 미리보기로 제목과 목록이 잘 보이는지 확인합니다.
