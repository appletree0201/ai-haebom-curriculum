# 5회차

## 오늘의 주제
오늘은 각 부서에서 생각해 온 자동화 후보를 공유하고, Markdown으로 `부서별 자동화 과제 카드`를 작성합니다.

구현은 이후 회차와 각자 실습에서 이어갑니다.

5회차의 핵심은 “무엇을 만들지”를 분명하게 정리하는 것입니다.

## 오늘의 목표
- VS Code에서 Markdown 파일을 어디에 만들고 어떻게 여는지 안다.
- Markdown 아주 기초 문법을 익힌다.
- 각 부서에서 생각해 온 자동화 후보를 공유한다.
- 후보 중 하나를 부서별 과제로 고른다.
- 입력, 작업, 출력, 확인 기준으로 과제를 정리한다.
- 이후 첫 구현의 기준이 되는 자동화 과제 카드를 만든다.

## 먼저 알아둘 말
오늘은 코드를 많이 쓰는 날이 아닙니다.

오늘은 자동화할 업무를 정리하는 날입니다.

자동화 과제 카드가 있어야 이후 Codex에게 구체적으로 요청할 수 있습니다.

```text
자동화 과제 카드 = 무엇을 만들지 정리한 설계도
```

이 카드는 이후 회차에서 계속 사용합니다.

- Codex에게 요청할 때 기준으로 쓴다.
- 과제가 너무 큰지 확인할 때 쓴다.
- 부서 안에서 자동화할 업무를 공유할 때 쓴다.
- 구현 중 방향이 흔들릴 때 다시 확인한다.
- 10회차 중간 공유 자료의 뼈대로 쓴다.

## Markdown을 배우는 이유
Markdown은 문서를 쉽고 일정하게 쓰기 위한 형식입니다.

오늘 Markdown을 배우는 이유는 문법 자체가 중요해서가 아닙니다.

자동화 과제 카드를 보기 좋고, Codex가 읽기 쉽게 만들기 위해서입니다.

Markdown 파일은 보통 `.md`로 끝납니다.

예시는 아래와 같습니다.

```text
department-automation-card.md
```

## Markdown은 어디서 작성하나
5회차에서는 Markdown을 `VS Code`에서 작성합니다.

Notion에 바로 쓰는 것이 아니라, 먼저 VS Code에서 `.md` 파일을 만듭니다.

이유는 간단합니다.

- Codex가 파일을 직접 읽고 도와줄 수 있다.
- 이후 구현 때 같은 작업공간에서 바로 이어갈 수 있다.
- 나중에 Git으로 변경 기록을 남기기 쉽다.
- Markdown 파일을 그대로 Notion에 붙여 넣거나 공유할 수 있다.

## VS Code에서 Markdown 파일 만드는 순서
아래 순서대로 하면 됩니다.

1. VS Code를 연다.
2. `File > Open Folder`를 눌러 실습 폴더를 연다.
3. 왼쪽 `Explorer`에서 새 파일 버튼을 누른다.
4. 파일 이름을 `department-automation-card.md`로 입력한다.
5. 가운데 편집 화면에 내용을 작성한다.
6. `Ctrl + S`로 저장한다.
7. 오른쪽 위 미리보기 버튼을 누르거나 `Ctrl + Shift + V`로 Markdown 미리보기를 연다.

`Explorer`가 보이지 않으면 왼쪽 파일 모양 아이콘을 누릅니다.

단축키가 잘 안 되면 명령 팔레트에서 찾을 수 있습니다.

```text
Ctrl + Shift + P
Markdown: Open Preview
```

처음에는 미리보기가 꼭 필요하지는 않습니다.

하지만 제목과 목록이 잘 보이는지 확인하면 Markdown이 어떻게 보이는지 이해하기 쉽습니다.

## Markdown 아주 기초 문법
오늘은 10분만 다룹니다.

아래 정도만 알면 자동화 과제 카드를 쓸 수 있습니다.

### 제목
```md
# 큰 제목
## 소제목
```

### 목록
```md
- 첫 번째 항목
- 두 번째 항목
- 세 번째 항목
```

### 순서 있는 목록
```md
1. 먼저 할 일
2. 다음 할 일
3. 마지막 할 일
```

### 파일명이나 짧은 용어 표시
```md
`AGENTS.md`
`department-automation-card.md`
```

### 예시 문장 묶기
````md
```text
입력:
작업:
출력:
확인:
```
````

이 정도면 오늘 실습에는 충분합니다.

## 오늘 만들 결과물
오늘의 결과물은 `부서별 자동화 과제 카드 1개`입니다.

완성된 프로그램이 아닙니다.

이후 만들기 위해 필요한 기준 문서입니다.

작성 위치는 VS Code 안의 실습 폴더입니다.

파일명 예시는 아래와 같습니다.

```text
department-automation-card.md
```

## 자동화 과제 카드 템플릿
오늘 사용할 공식 템플릿입니다.

```md
# 부서별 자동화 과제 카드

## 부서명

## 업무 이름

## 현재 하는 방식

## 반복되는 부분

## 자동화하고 싶은 부분

## 입력

## 작업

## 출력

## 확인

## 사람이 반드시 확인할 부분

## 첫 구현 범위
```

각 항목은 길게 쓰지 않아도 됩니다.

처음에는 한두 문장으로 충분합니다.

## 카드 작성 예시
아래는 4회차 사례를 카드로 바꾼 예시입니다.

```md
# 부서별 자동화 과제 카드

## 부서명
교육 운영 담당 부서

## 업무 이름
홈페이지 문의 자동 분류와 답변 초안 작성

## 현재 하는 방식
담당자가 홈페이지 문의를 읽고 유형을 판단한 뒤 답변 초안을 작성한다.

## 반복되는 부분
- 문의 내용을 읽는다.
- 문의 유형을 나눈다.
- 비슷한 답변 초안을 작성한다.
- 추가 확인이 필요한 정보를 묻는다.

## 자동화하고 싶은 부분
문의 내용을 넣으면 유형과 답변 초안이 나오면 좋겠다.

## 입력
홈페이지 문의 내용

## 작업
문의 유형 분류, 답변 초안 작성

## 출력
분류명, 답변 초안

## 확인
분류가 맞는지, 답변이 너무 단정적이지 않은지 확인한다.

## 사람이 반드시 확인할 부분
법령, 인정 여부, 증빙자료, 최종 답변 문구는 담당자가 확인한다.

## 첫 구현 범위
질문 한 문장을 입력하면 분류명과 답변 초안이 텍스트로 나오게 한다.
```

## 좋은 자동화 후보의 기준
좋은 후보는 아래 조건을 많이 만족합니다.

- 자주 반복된다.
- 입력이 비교적 분명하다.
- 결과를 확인할 수 있다.
- 처음 범위를 작게 줄일 수 있다.
- 사람이 마지막에 확인할 수 있다.

반대로 처음부터 피해야 할 후보도 있습니다.

- 한 번만 하는 일
- 기준이 전혀 정해지지 않은 일
- 결과가 맞는지 확인하기 어려운 일
- 법적 판단을 AI가 바로 확정해야 하는 일
- 여러 부서 시스템을 한 번에 바꿔야 하는 일

## 오늘의 진행 순서
1. 4회차 이후 생각해 온 자동화 후보를 꺼낸다.
2. VS Code에서 실습 폴더를 연다.
3. `department-automation-card.md` 파일을 만든다.
4. Markdown 아주 기초 문법을 10분만 본다.
5. 부서별로 후보를 공유한다.
6. 오늘 카드로 만들 후보 하나를 고른다.
7. 자동화 과제 카드 템플릿을 복사한다.
8. 입력, 작업, 출력, 확인을 먼저 채운다.
9. 사람이 반드시 확인할 부분을 적는다.
10. 첫 구현 범위를 한 줄로 정한다.

## 진행 팁
처음부터 멋진 과제를 고르려고 하지 않습니다.

작고 반복되는 일이 더 좋습니다.

예시는 아래와 같습니다.

- 문의 내용을 유형별로 나누기
- 반복 답변 초안 만들기
- 엑셀 명단에서 부서별 인원 수 세기
- 제출 파일 이름 규칙 확인하기
- 신청서에서 빠진 항목 찾기
- 회의 메모를 할 일 목록으로 정리하기

## 이후 구현과 연결하기
오늘 만든 자동화 과제 카드는 이후 구현을 시작할 때 기준 문서로 사용합니다.

예를 들어 카드에 아래처럼 적혀 있다면:

```text
입력: 홈페이지 문의 내용
작업: 문의 유형 분류, 답변 초안 작성
출력: 분류명, 답변 초안
확인: 분류가 맞는지, 답변이 너무 단정적이지 않은지 확인
```

이후 첫 구현 요청은 이렇게 바꿀 수 있습니다.

```text
아래 자동화 과제 카드를 기준으로 첫 구현 범위를 정해줘.
처음에는 질문 한 문장을 입력하면 분류명과 답변 초안이 텍스트로 나오게 하고 싶어.
아직 엑셀 저장이나 홈페이지 등록은 하지 마.
```

이렇게 카드가 있으면 Codex에게 요청하기 쉬워집니다.
