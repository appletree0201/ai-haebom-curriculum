Obsidian과 LLM Wiki로 회의자료를 지식으로 쌓기

회의자료를 한 번 요약하고 끝내는 것이 아니라, 부서별 안건, 후속조치, 반복 현안, 자동화 후보로 나누어 계속 쌓이는 위키로 만드는 흐름을 봅니다.

오늘의 완료 기준

  • Obsidian을 정리된 위키를 보는 창으로 이해
  • LLM Wiki와 일반 요약의 차이 이해
  • `raw/`, `wiki/`, `Output/` 역할 재확인
  • 회의자료 PDF가 위키로 정리되는 흐름 확인
  • 내부자료 취급 주의사항 확인

실제 내부 회의자료 내용은 배포 자료에 넣지 않습니다.

자료를 보는 순서

설명자료로 개념을 잡고, 시연자료로 운영자 노트북에서 보여줄 흐름을 본 뒤, 요약 가이드로 집에서 비슷한 자료를 떠올려 봅니다.

7회차 현장 흐름

도구 기능을 많이 배우기보다, 회의자료가 지식 위키로 바뀌는 장면을 중심으로 봅니다.

Obsidian 소개 Obsidian을 Markdown 노트와 연결을 보는 도구로 설명합니다.
LLM Wiki 구조 `raw/`, `wiki/`, `Output/` 역할을 다시 확인합니다.
PDF 반영 시연 운영자 노트북에서 회의자료 PDF를 위키로 반영하는 흐름을 보여 줍니다.
위키 확인 회의 요약, 부서별 안건, 후속조치, 자동화 후보 페이지를 확인합니다.
활용 질문 나중에 다시 찾을 정보와 자동화 후보를 질문으로 뽑아 봅니다.

집에서 할 일

내 업무에서 계속 쌓이는 자료 하나를 고르고, 어떤 지식으로 바꿀 수 있는지 적어 봅니다.

  • 매주 또는 매월 반복해서 쌓이는 자료를 하나 고릅니다.
  • 그 자료에서 나중에 다시 찾고 싶은 정보를 적습니다.
  • 부서별, 주제별, 일정별로 나눌 수 있는 항목을 찾습니다.
  • 후속조치로 보이는 내용을 따로 표시합니다.
  • 자동화 후보가 될 만한 반복 정리 작업을 적습니다.
  • 8회차 전에 지원·협업 요청 카드를 작성합니다.
