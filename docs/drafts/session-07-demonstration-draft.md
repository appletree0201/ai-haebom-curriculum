# 7회차 시연내용

## 시연 목적
- Obsidian이 무엇을 보는 도구인지 보여 준다.
- LLM Wiki가 일반 요약과 어떻게 다른지 보여 준다.
- 회의자료 PDF가 `raw/`에서 `wiki/`로 정리되는 흐름을 보여 준다.
- 회의자료에서 부서별 안건, 후속조치, 자동화 후보가 분리되는 모습을 보여 준다.
- 실제 내부자료를 다룰 때 주의할 점을 강조한다.

## 운영 전제
실제 시연은 AI 해봄 운영자의 별도 노트북에서 진행합니다.

배포 자료에는 실제 임원 티타임 회의자료 원문을 넣지 않습니다.

시연 화면에서도 민감한 정보가 보이지 않도록 사전에 확인합니다.

## 오늘 보여줄 핵심
```text
회의자료 PDF
-> raw/ 에 원본 보관
-> Codex가 읽고 wiki/ 정리
-> Obsidian에서 연결 구조 확인
-> 후속조치와 자동화 후보를 질문으로 다시 활용
```

## 1. Obsidian 소개
처음에는 Obsidian을 어렵게 설명하지 않습니다.

아래처럼 말합니다.

```text
Obsidian은 Markdown 노트를 보기 좋게 열고,
노트끼리 연결해서 볼 수 있는 도구입니다.
```

오늘은 Obsidian을 자료 작성 도구라기보다 `정리된 위키를 보는 창`으로 보여 줍니다.

## 2. Codex와 Obsidian 역할 나누기
역할을 분명하게 나눕니다.

```text
Codex = 원본 자료를 읽고 위키를 정리하는 작업자
Obsidian = 정리된 위키를 보고 연결을 따라가는 화면
```

이 구분을 먼저 해두면 초보자가 덜 헷갈립니다.

## 3. LLM Wiki 구조 보여주기
폴더 구조를 보여 줍니다.

```text
raw/
wiki/
Output/
```

설명 멘트입니다.

```text
raw는 원본 보관소입니다.
wiki는 AI가 정리한 지식 위키입니다.
Output은 배포하거나 공유할 결과물입니다.
```

## 4. 실제 PDF 넣기
운영자 노트북에서 준비한 임원 티타임 회의자료 PDF를 사용합니다.

예시 위치입니다.

```text
raw/meetings/
```

원본 PDF는 수정하지 않는다고 설명합니다.

```text
원본은 raw에 두고 수정하지 않습니다.
Codex는 원본을 읽고 wiki 쪽에 정리 결과를 만듭니다.
```

## 5. Codex 요청하기
Codex에게 아래와 같이 요청합니다.

```text
raw/meetings/ 폴더에 새로 넣은 회의자료 PDF를 LLM Wiki 방식으로 반영해줘.

회의자료 요약, 부서별 안건, 후속조치 후보, 자동화 후보를 분리해서 정리하고,
관련 위키 페이지를 만들거나 갱신해줘.

wiki/index.md와 wiki/log.md도 함께 갱신해줘.

원본 PDF는 수정하지 마.
```

## 6. 생성 결과 보기
생성될 수 있는 결과를 순서대로 보여 줍니다.

```text
wiki/meetings/...
wiki/departments/...
wiki/topics/...
wiki/trackers/...
wiki/index.md
wiki/log.md
```

실제 파일명은 자료에 따라 달라질 수 있다고 설명합니다.

## 7. 회의 요약 페이지 보기
회의 요약 페이지에서 아래 항목을 확인합니다.

- 회의 일자
- 주요 안건
- 핵심 요약
- 관련 부서
- 관련 주제
- 후속조치 후보

## 8. 부서별 안건 페이지 보기
부서별 페이지에서는 특정 부서와 관련된 안건만 모아 볼 수 있다고 설명합니다.

예시 질문입니다.

```text
이번 회의자료에서 부서별 주요 안건을 정리해줘.
```

## 9. 후속조치 페이지 보기
후속조치 페이지에서는 누가 무엇을 해야 하는지 추적할 수 있다고 설명합니다.

예시 질문입니다.

```text
후속조치로 보이는 항목만 따로 뽑아줘.
```

## 10. 자동화 후보 페이지 보기
자동화 후보 페이지에서는 반복 업무로 보이는 항목을 모아 볼 수 있다고 설명합니다.

예시 질문입니다.

```text
자동화 후보가 될 만한 반복 업무를 찾아줘.
```

여기서 5회차 자동화 과제 카드와 연결합니다.

```text
자동화 후보가 보이면 다시 입력, 작업, 출력, 확인 기준으로 카드화할 수 있습니다.
```

## 11. Obsidian에서 링크 확인
Obsidian에서 아래를 보여 줍니다.

- 회의 페이지에서 부서 페이지로 이동
- 회의 페이지에서 주제 페이지로 이동
- 자동화 후보 페이지로 이동
- `index.md`에서 관련 페이지 찾기

그래프 뷰는 깊게 설명하지 않습니다.

연결되어 있다는 느낌만 보여 줍니다.

## 12. 내부자료 주의사항 말하기
시연 마지막에 반드시 말합니다.

```text
실제 회의자료는 외부 도구에 무단 업로드하지 않습니다.
민감한 이름, 수치, 내부 의사결정 내용은 배포 자료에 넣지 않습니다.
AI가 만든 정리 결과는 초안이므로 담당자가 확인해야 합니다.
```

## 시연 순서
1. Obsidian을 정리된 위키를 보는 창으로 소개한다.
2. Codex와 Obsidian의 역할을 나눈다.
3. `raw/`, `wiki/`, `Output/` 구조를 보여 준다.
4. 운영자 노트북에서 실제 회의자료 PDF를 `raw/meetings/`에 둔다.
5. Codex에게 LLM Wiki 반영 요청을 한다.
6. 생성된 회의 요약 페이지를 본다.
7. 부서별 안건 페이지를 본다.
8. 후속조치 페이지를 본다.
9. 자동화 후보 페이지를 본다.
10. Obsidian에서 링크를 따라가 본다.
11. 내부자료 취급 주의사항을 다시 말한다.

## 참가자에게 던질 질문
- 우리 업무에서 매주 또는 매월 쌓이는 자료는 무엇인가?
- 그 자료에서 나중에 다시 찾고 싶은 정보는 무엇인가?
- 회의자료에서 자동으로 뽑히면 좋은 항목은 무엇인가?
- 부서별로 나눠 보면 편한 정보는 무엇인가?
- 자동화 후보로 이어질 수 있는 반복 업무는 무엇인가?

## 보조 샘플 요청
집에서 비슷한 자료를 정리해 보고 싶을 때 쓸 수 있는 요청입니다.

```text
이 자료를 LLM Wiki 방식으로 정리한다고 가정하고,
회의 요약, 주요 안건, 후속조치, 자동화 후보로 나눠줘.
```

```text
이 자료에서 나중에 다시 찾고 싶은 정보를 항목별로 정리해줘.
```

```text
이 자료에서 자동화 후보가 될 만한 반복 업무를 찾아줘.
입력, 작업, 출력, 확인 기준으로 정리해줘.
```

## 마무리
7회차 시연의 핵심은 회의자료를 한 번 요약하고 끝내는 것이 아닙니다.

회의자료에서 나온 안건, 부서, 후속조치, 자동화 후보를 계속 쌓아 가는 흐름을 보는 것입니다.
