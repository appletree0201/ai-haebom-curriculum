# 5회차 시연내용

## 시연 목적
- Markdown을 VS Code에서 어디에 작성하는지 보여 준다.
- Markdown 아주 기초 문법을 짧게 보여 준다.
- 자동화 후보가 Markdown 과제 카드로 바뀌는 과정을 보여 준다.
- 4회차 사례를 5회차 카드 작성 예시로 연결한다.
- 이후 첫 구현 범위가 카드에서 어떻게 나오는지 보여 준다.

## 오늘 보여줄 핵심
오늘의 핵심은 아래 흐름입니다.

```text
자동화 후보
-> Markdown 카드
-> 입력, 작업, 출력, 확인 정리
-> 첫 구현 범위 선택
```

오늘은 구현보다 정리가 중요합니다.

## 준비
- VS Code가 열린 상태
- 새 Markdown 파일을 만들 수 있는 폴더
- 파일명 예시: `department-automation-card.md`
- 4회차 홈페이지 문의 자동화 사례
- 자동화 과제 카드 템플릿

## 1. VS Code에서 실습 폴더 열기
먼저 Markdown을 어디에 작성할지 보여 줍니다.

참가자에게 아래처럼 설명합니다.

```text
오늘 작성할 Markdown 파일은 VS Code 안에서 만듭니다.
나중에 Codex가 이 파일을 읽고 첫 구현을 도와줄 수 있어야 하기 때문입니다.
```

시연 순서입니다.

1. VS Code를 연다.
2. `File > Open Folder`를 누른다.
3. 실습 폴더를 선택한다.
4. 왼쪽 `Explorer`에 폴더가 열렸는지 확인한다.

`Explorer`가 보이지 않으면 왼쪽 파일 모양 아이콘을 누른다고 설명합니다.

## 2. Markdown 파일 만들기
VS Code에서 새 파일을 만듭니다.

왼쪽 `Explorer`에서 새 파일 버튼을 누릅니다.

파일명은 아래처럼 보여 줍니다.

```text
department-automation-card.md
```

`.md`는 Markdown 문서라는 뜻입니다.

파일을 만든 뒤 `Ctrl + S`로 저장합니다.

## 3. Markdown 미리보기 열기
작성한 Markdown이 어떻게 보이는지 미리보기를 열어 봅니다.

아래 방법 중 하나를 보여 줍니다.

- 오른쪽 위 미리보기 버튼을 누른다.
- `Ctrl + Shift + V`를 누른다.
- `Ctrl + Shift + P`를 누르고 `Markdown: Open Preview`를 검색한다.

초보자에게는 이렇게 설명합니다.

```text
왼쪽은 우리가 쓰는 원본이고,
미리보기는 다른 사람이 읽을 때 보이는 모습입니다.
```

미리보기가 열리지 않아도 실습은 계속할 수 있습니다.

중요한 것은 `.md` 파일을 만들고 저장하는 것입니다.

## 4. Markdown 아주 기초 문법 보여주기
아래만 짧게 보여 줍니다.

```md
# 큰 제목
## 소제목
- 목록
1. 순서 있는 목록
`파일명`
```

예시 문장을 묶을 때는 아래처럼 씁니다.

````md
```text
입력:
작업:
출력:
확인:
```
````

설명은 길게 하지 않습니다.

오늘은 문법을 외우는 시간이 아니라 과제 카드를 쓰는 시간입니다.

## 5. 자동화 후보 보여주기
후보 업무를 한 문장으로 보여 줍니다.

```text
홈페이지 문의를 읽고 유형별로 나눈 뒤 답변 초안을 작성한다.
```

이 문장은 아직 과제 카드가 아닙니다.

너무 뭉뚱그려져 있습니다.

그래서 Markdown 템플릿에 넣어 정리합니다.

## 6. 카드 템플릿 붙여 넣기
아래 템플릿을 새 Markdown 파일에 붙여 넣습니다.

```md
# 부서별 자동화 과제 카드

## 부서명

## 업무 이름

## 현재 하는 방식

## 반복되는 부분

## 자동화하고 싶은 부분

## 입력

## 작업

## 출력

## 확인

## 사람이 반드시 확인할 부분

## 첫 구현 범위
```

## 7. 예시 카드 채우기
4회차 사례를 기준으로 일부 항목을 채웁니다.

```md
# 부서별 자동화 과제 카드

## 부서명
교육 운영 담당 부서

## 업무 이름
홈페이지 문의 자동 분류와 답변 초안 작성

## 현재 하는 방식
담당자가 홈페이지 문의를 읽고 유형을 판단한 뒤 답변 초안을 작성한다.

## 반복되는 부분
- 문의 내용을 읽는다.
- 문의 유형을 나눈다.
- 비슷한 답변 초안을 작성한다.
- 추가 확인이 필요한 정보를 묻는다.

## 자동화하고 싶은 부분
문의 내용을 넣으면 유형과 답변 초안이 나오면 좋겠다.

## 입력
홈페이지 문의 내용

## 작업
문의 유형 분류, 답변 초안 작성

## 출력
분류명, 답변 초안

## 확인
분류가 맞는지, 답변이 너무 단정적이지 않은지 확인한다.

## 사람이 반드시 확인할 부분
법령, 인정 여부, 증빙자료, 최종 답변 문구는 담당자가 확인한다.

## 첫 구현 범위
질문 한 문장을 입력하면 분류명과 답변 초안이 텍스트로 나오게 한다.
```

## 8. 좋은 카드인지 확인하기
작성한 뒤 아래 질문으로 확인합니다.

- 입력이 분명한가?
- 작업이 한두 가지로 좁혀졌는가?
- 출력이 눈에 보이는 형태인가?
- 결과가 맞는지 확인할 방법이 있는가?
- 사람이 확인해야 할 부분이 적혀 있는가?
- 첫 구현 범위가 너무 크지 않은가?

## 9. 이후 첫 요청으로 바꾸기
카드를 바탕으로 이후 첫 요청을 만듭니다.

```text
아래 자동화 과제 카드를 기준으로 첫 구현 범위를 정해줘.
처음에는 질문 한 문장을 입력하면 분류명과 답변 초안이 텍스트로 나오게 하고 싶어.
아직 엑셀 저장이나 홈페이지 등록은 하지 마.
```

이 요청을 보여 주면서 카드가 왜 필요한지 설명합니다.

```text
카드는 Codex에게 줄 요청의 재료입니다.
카드가 분명하면 첫 구현 요청도 분명해집니다.
```

## 시연 순서
1. VS Code에서 실습 폴더를 연다.
2. `department-automation-card.md` 파일을 만든다.
3. Markdown 미리보기를 여는 방법을 보여 준다.
4. Markdown 기초 문법을 10분 이내로 보여 준다.
5. 자동화 후보 한 문장을 보여 준다.
6. 과제 카드 템플릿을 붙여 넣는다.
7. 입력, 작업, 출력, 확인을 먼저 채운다.
8. 사람이 반드시 확인할 부분을 적는다.
9. 첫 구현 범위를 한 줄로 정한다.
10. 이후 첫 요청 문장으로 바꿔 본다.

## 참가자에게 던질 질문
- 우리 부서에서 반복해서 처리하는 업무는 무엇인가?
- 그 업무의 입력은 무엇인가?
- 결과는 어떤 모양으로 나오면 좋은가?
- 사람이 반드시 확인해야 하는 부분은 무엇인가?
- 처음 구현은 어디까지만 하면 충분한가?

## 보조 샘플 요청
참가자가 카드 작성 중 막혔을 때 쓸 수 있는 요청입니다.

```text
아래 자동화 후보를 입력, 작업, 출력, 확인 기준으로 나눠줘.
너무 큰 부분이 있으면 첫 구현 범위를 작게 제안해줘.
```

```text
아래 자동화 과제 카드에서 사람이 반드시 확인해야 할 부분을 찾아줘.
AI가 확정하면 위험한 부분도 따로 표시해줘.
```

## 마무리
5회차 시연의 핵심은 자동화 후보를 Markdown 카드로 바꾸는 것입니다.

이 카드가 있어야 이후 Codex에게 구체적으로 첫 구현을 요청할 수 있습니다.
