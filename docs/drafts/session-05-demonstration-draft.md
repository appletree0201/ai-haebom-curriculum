# 5회차 시연내용

## 시연 목적
5회차 시연은 VS Code에서 Markdown 파일을 만들고 자동화 과제 카드를 작성하는 흐름을 보여줍니다.

목적은 Markdown 문법을 많이 외우는 것이 아니라, 자동화 과제를 한 장으로 정리하는 과정을 보는 것입니다.

## 준비 상태
- VS Code가 실행됩니다.
- 실습 폴더가 열려 있습니다.
- 새 Markdown 파일을 만들 수 있습니다.
- 과제 카드 템플릿이 준비되어 있습니다.

## 진행 흐름
1. VS Code에서 실습 폴더를 엽니다.
2. `department-automation-card.md` 파일을 만듭니다.
3. 제목과 목록을 입력합니다.
4. Markdown 미리보기를 엽니다.
5. 과제 카드 템플릿을 붙여 넣습니다.
6. 예시 업무 하나를 짧게 채웁니다.
7. 결과가 읽기 좋은지 확인합니다.

## 화면에서 보여줄 것
### 1. 새 Markdown 파일 만들기
파일 이름을 `department-automation-card.md`로 만듭니다.

확인할 점은 `.md` 확장자입니다.

### 2. 기본 문법
아래 세 가지만 보여줍니다.

```md
# 제목

- 목록
- 목록

`파일명`
```

### 3. 미리보기
Markdown 미리보기를 열어 제목과 목록이 어떻게 보이는지 확인합니다.

### 4. 과제 카드 작성
템플릿에 아래 항목을 채웁니다.

- 업무 이름
- 반복되는 일
- 입력 자료
- 원하는 결과물
- 확인 기준
- 도움받고 싶은 부분

## 요청 예시
```text
현재 폴더에 department-automation-card.md 파일을 만들고,
부서별 자동화 과제 카드 템플릿을 넣어줘.
항목은 업무 이름, 반복되는 일, 입력 자료, 원하는 결과물, 확인 기준, 도움받고 싶은 부분으로 해줘.
```

## 결과 확인 기준
- 파일이 실습 폴더 안에 만들어졌는지 확인합니다.
- 제목과 목록이 잘 보이는지 확인합니다.
- 자동화 과제가 너무 크지 않은지 확인합니다.
- 확인 기준이 적혀 있는지 확인합니다.

## 함께 확인할 포인트
- Markdown은 어렵게 꾸미는 문서가 아닙니다.
- 자동화 과제를 Codex가 읽기 좋게 정리하는 도구입니다.
- 빈칸을 완벽하게 채우지 않아도 됩니다.
- 오늘은 구현보다 과제 정의가 중요합니다.

## 마무리 질문
- 내 과제의 입력 자료는 무엇인가요?
- 결과물은 어떤 파일이나 표로 나오면 좋나요?
- 사람이 꼭 확인해야 할 기준은 무엇인가요?
