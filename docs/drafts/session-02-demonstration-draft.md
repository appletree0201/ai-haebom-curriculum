# 2회차 시연내용

## 시연 목적
2회차 시연의 목적은 `AGENTS.md`가 자동으로 생기는 문서가 아니라는 점을 보여주고, 사람이 직접 만들고 수정하는 흐름을 눈으로 따라가게 하는 것입니다.

또한 Codex가 작업 전에 어떤 지침을 읽는지, 그리고 `skills`가 반복 작업 절차라는 점을 아주 짧게 보여줍니다.

## 시연 준비
- `VS Code` 실행 가능 상태
- 작업 폴더 열기
- `AI 해봄` 예시 작업공간의 루트 `AGENTS.md` 확인 가능
- `AI 해봄` 예시 작업공간의 `raw/AGENTS.md` 확인 가능
- 빈 개인 실습 폴더에는 `AGENTS.md`가 없을 수 있다는 설명 준비
- 샘플로 보여줄 쉬운 말투 규칙 준비
- `profile-sketch-card` 시연용 사진 1~2장 준비
- 사진 사용 동의 여부 확인

### 준비를 왜 하는가
- `AGENTS.md`를 직접 열어 봐야 자동 생성이 아니라는 점을 보여줄 수 있습니다.
- 루트와 하위 폴더 문서를 함께 열어야 규칙 우선순위를 설명할 수 있습니다.
- 참가자 개인 폴더에는 처음에 해당 파일이 없을 수 있다는 점을 먼저 말해야 혼란이 줄어듭니다.
- 말투 규칙은 결과가 바로 보여서 “직접 만든다”는 느낌이 살아납니다.
- 사진 기반 예시는 `skills`가 반복 가능한 작업 절차라는 점을 눈으로 보여주기 좋습니다.
- 실제 사람 사진은 반드시 허락된 사진만 사용해야 합니다.

## 미리 알아둘 말
2회차는 설명이 아니라 “작업 기준을 직접 확인하는 시간”입니다.

참가자는 모든 세부 규칙을 외울 필요가 없습니다.

대신 다음 세 가지를 기억하면 됩니다.

- `AGENTS.md`는 사람이 만든다.
- Codex는 그 문서를 읽고 따른다.
- 더 가까운 폴더의 규칙이 더 우선할 수 있다.

## 시연 순서
1. `VS Code`를 연다.
2. `AI 해봄` 예시 작업 폴더를 연다.
3. 루트 `AGENTS.md`를 연다.
4. `raw/AGENTS.md`를 열어 비교한다.
5. 참가자 개인 실습 폴더에는 처음에 이 파일이 없을 수 있음을 설명한다.
6. 말투가 바로 바뀌는 쉬운 `AGENTS.md` 생성 예시를 보여준다.
7. `skills`가 무엇인지 짧게 설명한다.
8. `profile-sketch-card` 예시로 같은 스타일이 반복되는 모습을 보여준다.
9. 아주 작은 요청을 보내서 규칙이 어떻게 적용되는지 본다.
10. 결과를 확인한다.

### 이 순서가 중요한 이유
1회차에서는 도구를 여는 법을 봤다면, 2회차에서는 그 도구가 읽는 규칙을 봐야 합니다.

그래서 먼저 문서를 열고, 그다음에 요청하고, 마지막에 결과를 확인하는 순서가 자연스럽습니다.

## 단계별 시연 내용

### 1. VS Code 열기
- 무엇을 보여줄지: 작업 화면을 연다.
- 왜 보여줄지: 문서와 파일을 직접 보여주기 위해서다.
- 참가자가 봐야 할 포인트: 왼쪽 파일 목록과 가운데 편집 화면

#### 더 자세히
- `AI 해봄` 예시 작업 폴더가 열린 상태를 보여준다.
- 파일 목록에서 `AGENTS.md`가 보이는 위치를 짚어준다.
- 참가자 개인 실습 폴더에는 이 파일이 아직 없을 수 있다고 미리 말한다.

### 2. 루트 AGENTS.md 열기
- 무엇을 보여줄지: 루트의 `AGENTS.md`를 직접 연다.
- 왜 보여줄지: Codex가 기준으로 읽는 문서를 실제로 보여주기 위해서다.
- 참가자가 봐야 할 포인트: 전체 작업공간 기준이라는 점

#### 더 자세히
- 루트 `AGENTS.md`에는 전체 작업공간의 기본 규칙이 들어 있다는 점을 말한다.
- 이 문서는 자동 생성이 아니라 사람이 직접 작성하는 파일이라는 점을 다시 강조한다.

### 3. raw/AGENTS.md 열기
- 무엇을 보여줄지: `raw/AGENTS.md`를 연다.
- 왜 보여줄지: 같은 작업공간 안에서도 폴더별 규칙이 다를 수 있다는 점을 보여주기 위해서다.
- 참가자가 봐야 할 포인트: 원본 자료를 다루는 기준

#### 더 자세히
- `raw/AGENTS.md`는 원본을 수정하지 않는다는 규칙을 담고 있다는 점을 짚는다.
- 루트 문서와 비교해서 무엇이 다른지 보여준다.

### 4. 비교해서 보기
- 무엇을 보여줄지: 두 문서의 역할 차이를 비교한다.
- 왜 보여줄지: Codex가 왜 상위 규칙과 하위 규칙을 같이 읽는지 이해시키기 위해서다.
- 참가자가 봐야 할 포인트: “전체 규칙”과 “폴더 규칙”의 차이

#### 더 자세히
- 루트 문서는 공통 기준, `raw/AGENTS.md`는 원본 자료용 기준이라고 정리한다.
- 더 가까운 폴더의 규칙이 실제 작업에 더 직접적일 수 있다는 점을 설명한다.

### 5. 개인 실습 폴더에는 없을 수 있다는 점 설명
- 무엇을 보여줄지: 새로 만든 폴더에는 `AGENTS.md`가 없을 수 있다는 점을 설명한다.
- 왜 보여줄지: 참가자가 “내 화면에는 왜 파일이 없지?”라고 헷갈리지 않게 하기 위해서다.
- 참가자가 봐야 할 포인트: `AGENTS.md`는 자동 생성 파일이 아니라 사람이 만드는 작업 기준이라는 점

#### 더 자세히
- `AI 해봄` 예시 작업공간에는 동호회 자료 관리를 위해 미리 만들어 둔 `AGENTS.md`가 있다고 말한다.
- 참가자 개인 실습 폴더에는 처음에 없을 수 있으며, 필요할 때 직접 만들면 된다고 설명한다.
- 파일이 없는 상태는 오류가 아니라고 말한다.

### 6. 아주 쉬운 AGENTS.md 생성 예시
- 무엇을 보여줄지: 말투가 바로 바뀌는 `AGENTS.md` 예시를 보여준다.
- 왜 보여줄지: “자동으로 생기는 파일”이 아니라 “직접 작성하는 파일”임을 확인시키기 위해서다.
- 참가자가 봐야 할 포인트: `AGENTS.md`에 적은 규칙이 Codex 답변에 바로 반영된다는 점

#### 더 자세히
- 처음에는 업무 규칙보다 말투 규칙이 더 쉽다고 설명한다.
- 아래 요청으로 개인 실습 폴더에 작은 `AGENTS.md`를 만들 수 있다고 보여준다.

```text
현재 폴더에 AGENTS.md를 만들고, 아래 규칙 3개를 넣어줘.

- 항상 한국어로 대답한다.
- 초보자도 이해할 수 있게 쉽게 설명한다.
- 답변 마지막에 "오늘도 해봄!"을 붙인다.
```

생성된 파일 예시는 아래처럼 보여준다.

```md
# AGENTS.md

- 항상 한국어로 대답한다.
- 초보자도 이해할 수 있게 쉽게 설명한다.
- 답변 마지막에 "오늘도 해봄!"을 붙인다.
```

그다음 아래 요청으로 규칙이 적용되는지 확인한다.

```text
AGENTS.md에 적힌 규칙을 읽고, AGENTS.md가 무엇인지 한 문장으로 설명해줘.
```

결과 마지막에 `오늘도 해봄!`이 붙으면 규칙이 적용된 것입니다.

마지막으로 실제 업무에서는 말투보다 저장 위치, 원본 보호, 설명 방식 같은 규칙을 적는다고 연결한다.

### 7. skills 설명
- 무엇을 보여줄지: `skills`가 무엇인지 짧게 설명한다.
- 왜 보여줄지: `AGENTS.md`와 헷갈리지 않게 하기 위해서다.
- 참가자가 봐야 할 포인트: 반복 작업 절차라는 점

#### 더 자세히
- `skills`는 자주 하는 작업을 위한 절차라는 점을 다시 말한다.
- 지금은 이름과 역할만 알면 충분하다는 점을 강조한다.

### 8. profile-sketch-card 예시
- 무엇을 보여줄지: 사진과 재미용 학습 키워드로 같은 스타일의 프로필 카드가 만들어지는 흐름을 보여준다.
- 왜 보여줄지: `skills`가 “반복 가능한 절차”라는 점을 눈으로 이해시키기 위해서다.
- 참가자가 봐야 할 포인트: 사진과 키워드는 바뀌어도 스타일과 작업 방식은 유지된다는 점

#### 더 자세히
- `profile-sketch-card`는 사진을 보고 사람을 분석하는 skill이 아니라고 먼저 말한다.
- 사진은 카드 그림을 만들기 위한 시각 참고 자료일 뿐이라고 설명한다.
- `작은 자동화 도전자`, `키보드 항해자`, `회의록 정리 장인` 같은 키워드는 재미용 학습 태그라고 말한다.
- 성격, 능력, 건강, 나이, 외모, 퍼스널컬러 판단은 하지 않는다고 설명한다.

#### 시연 요청 예시
`profile-sketch-card 스킬을 사용해서 이 사진을 바탕으로 스케치 노트 스타일의 프로필 카드 예시를 만들어줘. 키워드는 재미용 학습 태그로 정하고, 성격이나 외모 평가는 하지 마.`

#### 비교해서 보여줄 점
- 첫 번째 카드와 두 번째 카드의 사람은 다르다.
- 키워드도 다를 수 있다.
- 하지만 배경, 손그림 느낌, 메모 박스, 체크박스, 전체 구도는 비슷하게 유지된다.
- 이것이 skill을 쓰는 이유입니다.

### 9. 아주 작은 요청
- 무엇을 보여줄지: 규칙이 실제로 적용되는지 확인하는 아주 작은 요청을 보낸다.
- 왜 보여줄지: 문서를 읽는 것과 실제로 따르는 것은 다르기 때문이다.
- 참가자가 봐야 할 포인트: 요청 전후로 바뀐 부분

#### 더 자세히
- 예를 들어 `AGENTS.md`에 들어갈 규칙 한 줄 예시를 정리해 달라고 요청한다.
- 또는 `AGENTS.md`의 말투 규칙이 실제 답변에 반영되는지 확인해 달라고 요청한다.
- 또는 `AI 해봄` 예시 작업공간의 `raw/AGENTS.md`와 루트 `AGENTS.md`의 차이를 한 문장으로 요약해 달라고 요청한다.

### 10. 결과 확인
- 무엇을 보여줄지: 요청 결과가 맞는지 본다.
- 왜 보여줄지: 바로 확인하고 수정하는 습관을 보여주기 위해서다.
- 참가자가 봐야 할 포인트: 바뀐 문장과 적용 위치

## 시연 중 강조할 말
- `AGENTS.md`는 자동 생성되지 않는다.
- `AI 해봄` 예시 작업공간에는 미리 있지만, 개인 실습 폴더에는 처음에 없을 수 있다.
- 사람이 직접 만들고, 직접 고치고, Codex는 읽어서 따른다.
- 짧은 규칙이 가장 이해하기 쉽다.
- 처음에는 말투 규칙처럼 바로 보이는 예시가 좋다.
- 실제 업무에서는 말투보다 작업 기준을 적는다.
- `skills`는 반복 작업 절차로 생각하면 된다.
- 재미있는 이미지 예시를 쓰더라도 핵심은 “반복 가능한 작업 방식”이다.
- 실제 사람 사진을 사용할 때는 동의와 안전 경계를 먼저 확인한다.

## 막힘 대응
- 루트 문서와 하위 문서의 차이가 헷갈리면 비교 화면을 천천히 다시 보여준다.
- 참가자 화면에 `AGENTS.md`가 없으면 오류가 아니라고 설명하고, 필요할 때 만드는 파일이라고 다시 말한다.
- `skills`가 헷갈리면 “반복 작업 설명서”라고 다시 말해준다.
- 한 번에 이해가 안 되면, 이번에는 이름과 역할만 기억하게 하고 다음 단계로 넘긴다.

## 참가자 질문
- `AGENTS.md`를 왜 사람이 직접 만들어야 하는가
- 루트와 하위 폴더의 규칙이 왜 다를 수 있는가
- `skills`는 어떤 일을 위해 따로 묶어 두는가

## 마무리
이번 시연의 핵심은 `AGENTS.md`를 직접 만들고 읽는 구조를 이해하는 것입니다.

2회차를 끝내면 참가자는 “Codex는 기준 없이 움직이지 않는다”는 점과, 그 기준이 사람이 작성한 문서에 있다는 점을 이해하게 됩니다.
