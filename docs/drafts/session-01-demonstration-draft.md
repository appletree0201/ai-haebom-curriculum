# 1회차 시연내용

## 시연 목적
1회차 시연의 목적은 `VS Code`와 `Codex`를 실제로 연결하고, 초보자도 흐름을 눈으로 따라갈 수 있게 보여주는 것입니다.

설명보다 중요한 것은 `어디를 눌러서, 무엇을 확인하는지`를 직접 보는 것입니다.

이 시연은 "이 도구를 왜 쓰는지"와 "어떻게 시작하는지"를 동시에 보여줍니다.

처음 보는 사람에게는 말로만 설명하면 금방 놓칩니다.

그래서 화면, 순서, 결과를 같이 보여주는 것이 중요합니다.

## 시연 준비
- `VS Code` 공식 다운로드 사이트 접속 가능
- `VS Code` 설치 완료 또는 설치 파일 준비
- 한글 언어팩 설치 화면 확인 가능
- 확장 프로그램 화면 확인 가능
- 설치 체크리스트와 문제 해결 FAQ 안내 준비
- 작업 폴더 준비
- `Codex` 연결 가능 상태
- 로그인 확인
- 권한 확인
- 샘플로 보여줄 짧은 요청 1개 준비

### 준비를 왜 하는가
- 공식 다운로드 사이트를 보여줘야 참가자가 집에서 같은 경로로 설치할 수 있습니다.
- `VS Code`가 설치되어 있어야 실제 화면을 보여줄 수 있습니다.
- 한글 언어팩과 확장 프로그램 설치 위치를 보여줘야 초보자가 혼자 다시 따라 할 수 있습니다.
- 작업 폴더가 있어야 어디를 바꾸는지 설명할 수 있습니다.
- `Codex`가 연결되어 있어야 요청과 결과를 바로 보여줄 수 있습니다.
- 로그인과 권한을 먼저 확인해야 중간에 멈추지 않습니다.
- 샘플 요청은 너무 어려우면 안 됩니다. 아주 짧아야 합니다.

## 미리 알아둘 말
시연은 발표가 아니라 "보여주기"입니다.

중요한 것은 설명을 많이 하는 것이 아니라, 화면에서 실제로 무엇이 일어나는지를 보는 것입니다.

참가자는 모든 버튼 이름을 외울 필요가 없습니다.

대신 "어디서 시작하고, 어디서 결과를 확인하는지"를 기억하면 됩니다.

`AGENTS.md`와 `skills`는 2회차에서 자세히 다룹니다.

현장에서는 설치를 끝까지 같이 하지 않습니다.

설치 흐름, 확장 설치 위치, 막혔을 때 볼 지점만 시연하고 실제 설치와 샘플 실행은 집에서 체크리스트를 보며 진행합니다.

## 시연 순서
1. `VS Code` 공식 다운로드 사이트를 보여준다.
2. 설치 파일을 받는 위치와 설치 후 실행 방법을 설명한다.
3. `VS Code`를 연다.
4. 한글 언어팩 설치 위치를 보여준다.
5. 확장 프로그램 설치 방법과 권장 확장을 보여준다.
6. 작업 폴더를 연다.
7. `Codex` 연결 화면을 보여준다.
8. 로그인 상태를 확인한다.
9. 권한이 필요한 이유를 짧게 설명한다.
10. 아주 짧은 샘플 요청을 보낸다.
11. 결과가 어디에 반영되는지 보여준다.
12. 변경된 내용을 다시 확인한다.

### 이 순서가 중요한 이유
1번부터 12번까지는 서로 연결되어 있습니다.

설치가 되어 있는지 확인하고, 폴더를 열고, 연결하고, 요청하고, 결과를 보는 흐름이 이어져야 초보자가 전체 그림을 이해합니다.

중간 순서가 바뀌면 "무엇을 먼저 해야 하는지"를 놓치기 쉽습니다.

## 단계별 시연 내용

### 1. VS Code 다운로드 위치 확인
- 무엇을 보여줄지: 공식 다운로드 사이트와 `Download for Windows` 버튼을 보여준다.
- 왜 보여줄지: 초보자는 어디에서 받아야 하는지부터 막힐 수 있기 때문이다.
- 참가자가 봐야 할 포인트: 주소가 `https://code.visualstudio.com/`인지 확인

#### 더 자세히
- 브라우저에서 `https://code.visualstudio.com/`에 접속한다.
- `Download for Windows` 버튼 위치를 보여준다.
- 설치 파일을 받은 뒤 실행한다는 흐름만 설명한다.
- 이미 설치된 PC라면 실제 설치를 끝까지 반복하지 않아도 된다.

### 2. VS Code 설치와 실행
- 무엇을 보여줄지: 프로그램을 어떻게 여는지 보여준다.
- 왜 보여줄지: 초보자는 시작 화면부터 낯설기 때문이다.
- 참가자가 봐야 할 포인트: 폴더를 여는 위치와 화면 구성

#### 더 자세히
- 바탕화면이나 시작 메뉴에서 `VS Code`를 여는 모습을 보여준다.
- 설치 중에는 기본값으로 진행해도 된다는 점을 설명한다.
- 처음 열렸을 때 어떤 화면이 나오는지 보여준다.
- 아직 파일이 열리지 않은 상태와 폴더가 열린 상태의 차이를 보여준다.
- 참가자에게 "지금 어떤 화면인지"를 한 번 짚어준다.

### 3. 한글 언어팩 설치
- 무엇을 보여줄지: `Extensions`에서 한글 언어팩을 설치하는 화면을 보여준다.
- 왜 보여줄지: 영어 메뉴가 부담스러운 참가자가 많을 수 있기 때문이다.
- 참가자가 봐야 할 포인트: 검색어, 설치 버튼, 재시작 안내

#### 더 자세히
- 왼쪽 사이드바의 `Extensions` 아이콘을 누른다.
- 검색창에 `Korean Language Pack`을 입력한다.
- `Korean Language Pack for Visual Studio Code`를 찾는다.
- `Install` 버튼을 누르는 위치를 보여준다.
- 설치 후 `Restart` 안내가 나오면 다시 시작해야 한다고 설명한다.

### 4. 확장 프로그램 설치 방법
- 무엇을 보여줄지: 확장 프로그램을 검색하고 설치하는 공통 방법을 보여준다.
- 왜 보여줄지: 앞으로 `Python`, `Codex` 같은 도구를 설치할 때 계속 쓰는 화면이기 때문이다.
- 참가자가 봐야 할 포인트: 이름, 제공자, `Install` 버튼

#### 더 자세히
- 같은 `Extensions` 화면에서 검색창을 사용한다.
- `Python`을 검색해 설치 흐름을 보여준다.
- `Codex` 또는 `OpenAI Codex`를 검색해 현재 사용하는 확장을 찾는 방법을 보여준다.
- `Excel Viewer` 또는 엑셀/CSV 미리보기 확장을 검색해 설치 위치를 보여준다.
- 엑셀 뷰어는 향후 엑셀이나 CSV 자료를 확인하기 위한 사전 준비이며, 1회차에서는 설치 확인만 한다고 설명한다.
- 검색 결과가 여러 개면 `AI 해봄` 안내 화면의 이름과 제공자를 비교해야 한다고 설명한다.
- 설치 완료 후 버튼이 `Uninstall` 또는 `Disable`로 바뀌는지 확인한다.

### 5. 작업 폴더 열기
- 무엇을 보여줄지: 현재 작업할 폴더를 연다.
- 왜 보여줄지: 어디서 작업하는지 알아야 이후가 이해된다.
- 참가자가 봐야 할 포인트: 파일 트리와 폴더 구조

#### 더 자세히
- 왜 폴더가 필요한지 설명한다.
- 파일이 있는 위치를 보여준다.
- 왼쪽에 파일 목록이 어떻게 보이는지 보여준다.
- "이 폴더 안에서 작업한다"는 개념을 반복해서 말한다.

### 6. Codex 연결
- 무엇을 보여줄지: Codex를 연결하는 흐름을 보여준다.
- 왜 보여줄지: 실제 사용의 시작점이기 때문이다.
- 참가자가 봐야 할 포인트: 연결 상태와 응답 위치

#### 더 자세히
- Codex를 어디에서 여는지 보여준다.
- 연결되었는지 어떻게 확인하는지 보여준다.
- 연결이 안 될 때 어떤 메시지가 나오는지 짧게 언급한다.
- 참가자가 "지금 AI와 연결된 상태인지"를 알 수 있게 한다.

### 7. 로그인과 권한 확인
- 무엇을 보여줄지: 로그인 여부와 권한 확인 흐름을 보여준다.
- 왜 보여줄지: 초보자는 여기서 자주 막힌다.
- 참가자가 봐야 할 포인트: 에러가 날 때 어디를 먼저 보는지

#### 더 자세히
- 로그인 상태를 어디서 확인하는지 보여준다.
- 권한 메뉴를 열어 `기본 권한`, `전체 액세스`, `맞춤형(config.toml)`이 보이는 모습을 보여준다.
- 각 항목이 무엇을 의미하는지 아주 짧게 설명한다.
- 권한이 부족할 때 작업이 막힌다는 점을 설명한다.
- 문제가 생기면 어떤 메시지를 먼저 읽어야 하는지 보여준다.
- "안 되는 이유를 먼저 확인해야 한다"는 습관을 심어준다.

### 8. 짧은 샘플 요청
- 무엇을 보여줄지: 아주 간단한 요청을 보낸다.
- 왜 보여줄지: 큰 작업보다 작은 요청이 기본이기 때문이다.
- 참가자가 봐야 할 포인트: 요청 문장과 결과 반영

#### 더 자세히
- 아주 짧은 문장을 입력하는 모습을 보여준다.
- 요청이 길면 왜 안 좋은지 설명한다.
- 아래처럼 두 종류의 예시를 구분해서 보여준다.

#### 일반 챗GPT로도 가능한 예시
- `이 메일 답장 초안을 좀 더 공손하게 써줘.`
- `이 공지문을 더 짧고 읽기 쉽게 바꿔줘.`
- `이 업무 설명을 초보자도 이해할 수 있게 바꿔줘.`

이런 예시는 AI 대화 연습에는 좋지만, Codex의 강점은 덜 보입니다.

#### Codex 시연에 더 맞는 예시
- `현재 작업 폴더에 YYYY-MM-DD 형식의 md 파일을 만들고, 오늘 배운 내용을 3개 항목으로 정리해줘.`
- `현재 작업 폴더에 today-note.md 파일을 만들고, 오늘 확인한 내용과 내일 할 일을 구분해서 적어줘.`
- `현재 작업 폴더에 회의후속조치.md 파일을 만들고, 오늘 나온 할 일 3개를 정리해줘.`
- `현재 작업 폴더에 환경세팅기록.md 파일을 만들고, 오늘 확인한 설정과 막힌 점을 정리해줘.`

이런 예시는 실제 파일이 바뀌기 때문에 Codex 시연에 더 적합하다.

#### 시연에 가장 적합한 첫 샘플
- `현재 작업 폴더에 YYYY-MM-DD 형식의 md 파일을 만들고, 오늘 배운 내용을 3개 항목으로 정리해줘.`

이 문장은 파일 생성, 작업공간 이해, 결과 확인이 한 번에 드러납니다.

### 9. 결과 확인
- 무엇을 보여줄지: 실제로 파일이나 문구가 어떻게 바뀌었는지 본다.
- 왜 보여줄지: 요청만 하고 끝내면 안 되기 때문이다.
- 참가자가 봐야 할 포인트: 바뀐 위치와 바뀐 내용

#### 더 자세히
- 바뀐 파일이나 바뀐 문장을 천천히 보여준다.
- 어떤 부분이 바뀌었는지 짚어준다.
- 결과가 예상과 다를 수도 있다는 점을 말한다.
- 결과를 보고 다음 요청을 할 수 있다는 흐름을 보여준다.

## 시연 중 강조할 말
- 오늘은 복잡한 걸 만드는 날이 아니다.
- 처음에는 작게 요청하는 것이 중요하다.
- 결과를 보고, 필요한 부분만 고치면 된다.
- 이 방식이 앞으로의 기본 흐름이다.

### 추가로 강조할 말
- 한 번에 완벽하게 만들 필요는 없다.
- 먼저 보고, 그다음 고친다.
- 질문은 짧게, 요청은 작게 한다.
- 결과가 나오면 그때 판단한다.

## 막힘 대응
- 다운로드 사이트를 못 찾으면 주소를 직접 입력하게 한다.
- 한글 언어팩 검색이 안 되면 검색어를 `Korean Language Pack`으로 다시 입력하게 한다.
- 확장 검색 결과가 여러 개면 이름과 제공자를 `AI 해봄` 안내 화면과 비교하게 한다.
- 연결이 안 되면 설치와 로그인 화면까지만 보여준다.
- 권한 문제면 원인을 설명하고 다음 단계는 문서로 안내한다.
- 샘플 실행이 실패하면 요청 문장을 더 단순하게 바꾼다.

### 막히면 이렇게 넘긴다
1. 공식 다운로드 주소가 맞는지 확인한다.
2. 화면이 열리는지 확인한다.
3. 한글 언어팩과 확장 프로그램 설치 상태를 본다.
4. 연결이 되었는지 본다.
5. 로그인 상태를 확인한다.
6. 요청 문장을 더 짧게 바꾼다.
7. 시연이 멈추면 설명으로 대체하고 다음 자료로 넘긴다.

## 참가자 질문
- 지금 화면에서 어디가 가장 헷갈리는가
- 집에서 다시 해볼 때 제일 먼저 막힐 부분은 무엇인가
- 다음 회차에서 더 자세히 보고 싶은 부분은 무엇인가

### 질문을 왜 하는가
- 참가자가 어디서 막히는지 알아야 다음 자료를 더 잘 만들 수 있습니다.
- 초보자는 설명을 들을 때는 이해한 것처럼 보여도, 실제로는 다른 부분에서 막히는 경우가 많습니다.
- 질문을 통해 무엇을 더 자세히 써야 하는지 알 수 있습니다.

## 마무리
이번 시연의 핵심은 `Codex를 처음 연결하고, 짧게 요청하고, 결과를 확인하는 흐름`을 눈으로 보는 것입니다.

설명자료는 집에서 다시 읽는 용도이고, 시연내용은 현장에서 그 흐름을 따라가게 하는 용도입니다.

설치 체크리스트는 집에서 순서대로 따라 하는 자료이고, 문제 해결 FAQ는 막혔을 때 증상별로 확인하는 자료입니다.
