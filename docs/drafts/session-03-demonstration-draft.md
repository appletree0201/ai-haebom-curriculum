# 3회차 시연자료

## 시연 목적
- 큰 요청을 바로 실행하지 않는 흐름을 보여 준다.
- 플랜모드가 질문을 되받아 요구사항을 정리하는 과정을 보여 준다.
- `엑셀 명단 정리` 예시로 큰 요청이 작은 계획으로 바뀌는 모습을 보여 준다.
- 스킬은 “반복되는 계획 수립 방식은 나중에 묶을 수 있다” 정도로만 소개한다.

## 오늘 보여줄 핵심
오늘의 핵심은 자동화 결과물이 아닙니다.

핵심은 아래 흐름입니다.

```text
큰 요청
-> 플랜모드 질문
-> 답변
-> 작은 단계 계획
-> 첫 실행 요청
```

참가자는 “처음부터 완벽한 요청을 하지 않아도 된다”는 점을 이해하면 됩니다.

## 준비
- Codex가 열려 있는 VS Code 작업공간
- 플랜모드 또는 “바로 실행하지 말고 계획부터 세워줘” 요청을 사용할 준비
- 엑셀 명단 정리 상황 예시
- 화면에 보여줄 질문/답변 예시

## 시연용 큰 요청
```text
엑셀 명단을 보기 좋게 정리하고 싶어요.
```

이 요청은 일부러 막연하게 시작합니다.

바로 실행하지 않고, 플랜모드가 필요한 질문을 되묻게 하는 것이 목적입니다.

## 플랜모드 시작 요청
아래처럼 요청합니다.

```text
바로 실행하지 말고, 먼저 필요한 질문을 해줘.
내 답변을 바탕으로 작은 단계의 계획을 세워줘.
```

또는 한 번에 이렇게 말할 수 있습니다.

```text
엑셀 명단을 보기 좋게 정리하고 싶어요.
바로 실행하지 말고, 먼저 필요한 질문을 해주고 계획을 세워줘.
```

## 시연 대화 예시

### 1. 첫 질문
Codex가 이렇게 되묻는 흐름을 보여 줍니다.

```text
현재 이해: 엑셀 명단을 보기 좋게 정리하려는 상황입니다.
막힌 결정: 어떤 기준으로 정리해야 하는지가 아직 불분명합니다.
추천 답안: 먼저 열 이름, 정리 기준, 원하는 결과 형태를 확인하는 것이 좋습니다.
질문: 이 명단에서 가장 먼저 정리하고 싶은 기준은 무엇인가요?
```

사용자 답변:

```text
부서별로 나누고 싶어요.
```

### 2. 두 번째 질문
```text
현재 이해: 엑셀 명단을 부서별로 나누고 싶습니다.
막힌 결정: 결과를 어떤 형태로 받을지가 아직 정해지지 않았습니다.
추천 답안: 초보자 실습에서는 먼저 부서별 인원 수 요약표를 만드는 것이 쉽습니다.
질문: 결과는 부서별 인원 수 요약표로 볼까요, 아니면 부서별 명단을 따로 나눌까요?
```

사용자 답변:

```text
일단 부서별 인원 수 요약표가 좋겠습니다.
```

### 3. 계획 수립
```text
계획:
1. 엑셀 파일의 열 이름을 확인한다.
2. 부서가 적힌 열을 찾는다.
3. 부서별 인원 수를 센다.
4. 결과를 표로 정리한다.
5. 전체 인원 수가 원본과 맞는지 확인한다.
```

## 4칸 공식으로 확인
계획을 받은 뒤 아래 네 칸으로 다시 확인합니다.

```text
입력: 엑셀 명단 파일
작업: 부서별 인원 수 계산
출력: 부서명 / 인원 수 표
확인: 전체 합계가 원본 명단 인원 수와 같은지 보기
```

이 네 칸이 채워지면 요청이 작아진 것입니다.

## 첫 실행 요청으로 바꾸기
계획 전체를 한 번에 실행하지 않습니다.

먼저 첫 실행 요청만 만듭니다.

```text
엑셀 명단 파일의 열 이름을 먼저 확인해줘.
어떤 열이 부서 정보인지 후보를 알려줘.
아직 파일을 수정하지는 마.
```

이 요청은 작습니다.

입력은 엑셀 명단 파일이고, 작업은 열 이름 확인이며, 출력은 부서 열 후보입니다.

## 시연 순서
1. 큰 요청을 보여 준다.
2. 바로 실행하면 왜 위험한지 설명한다.
3. 플랜모드로 질문부터 해달라고 요청한다.
4. Codex가 되묻는 질문을 보여 준다.
5. 사용자가 짧게 답하는 모습을 보여 준다.
6. 두 번째 질문을 받고 한 번 더 답한다.
7. 작은 단계의 계획을 확인한다.
8. 계획을 4칸 공식으로 다시 정리한다.
9. 첫 실행 요청만 만든다.
10. 스킬은 나중에 반복 계획 양식으로 만들 수 있다고 짧게 연결한다.

## 시연에서 강조할 포인트
- 처음부터 완벽한 요청을 하지 않아도 된다.
- 큰 요청은 출발점으로 괜찮다.
- 중요한 것은 바로 실행하지 않고 질문을 되받는 것이다.
- 질문에 답할수록 계획이 선명해진다.
- 계획이 선명해져야 작은 실행 요청을 만들 수 있다.
- 오늘은 스킬을 만드는 날이 아니다.

## 스킬 연결 멘트
아래 정도로만 말합니다.

```text
이런 질문 방식이 반복되면 나중에는 스킬로 묶을 수 있습니다.
하지만 오늘은 스킬을 만드는 날이 아니라, 질문을 주고받으며 계획을 세우는 흐름을 익히는 날입니다.
```

## 참가자에게 던질 질문
- 내가 자주 하는 큰 요청은 무엇인가?
- 그 요청을 바로 실행하면 무엇이 불분명한가?
- AI가 나에게 되물어야 할 첫 질문은 무엇인가?
- 결과를 어떤 형태로 받아야 확인하기 쉬운가?

## 보조 샘플 요청
- `이 요청을 바로 실행하지 말고, 먼저 필요한 질문을 하나씩 해줘.`
- `내 답변을 바탕으로 실행 계획을 5단계 이내로 세워줘.`
- `각 단계마다 입력, 작업, 출력, 확인 기준을 적어줘.`
- `계획 중 첫 번째 단계만 실행 요청문으로 바꿔줘.`

## 마무리
오늘의 핵심은 자동화를 완성하는 것이 아닙니다.

`큰 요청을 플랜모드로 작게 나누는 것`입니다.

질문을 주고받아 계획을 세우는 능력이 있어야 4회차 실제 업무자동화 사례와 5회차 부서별 과제 카드 작성 흐름을 이해하기 쉽습니다.
