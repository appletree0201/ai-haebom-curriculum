# 2회차

## 오늘의 목표
- `AGENTS.md`가 무엇인지 이해한다.
- Codex가 왜 `AGENTS.md`를 먼저 읽는지 이해한다.
- 우리 작업공간에서 어떤 `AGENTS.md`가 적용되는지 본다.
- `AGENTS.md`는 자동 생성이 아니라 사람이 직접 만든다는 점을 안다.
- 처음 만든 실습 폴더에는 `AGENTS.md`가 없을 수 있다는 점을 안다.
- `skills`가 무엇인지 이해한다.
- 작은 요청으로 작업 기준을 확인하는 방법을 익힌다.

## 먼저 알아둘 말
- `AGENTS.md`는 작업 규칙을 적어 두는 문서입니다.
- `AGENTS.md`는 자동으로 생기지 않습니다. 사람이 직접 만들고 수정합니다.
- `skills`는 반복 작업을 위한 재사용 가능한 작업 절차입니다.
- 오늘은 두 개념을 외우는 날이 아니라, 왜 필요한지 감을 잡는 날입니다.

## 왜 이걸 배우는가
Codex는 아무 기준 없이 움직이는 도구가 아닙니다.

어떤 폴더를 열었는지, 어떤 문서를 먼저 읽었는지, 어떤 작업 규칙이 있는지에 따라 행동이 달라질 수 있습니다.

그래서 초보자도 `AGENTS.md`를 먼저 보고 시작하는 습관이 중요합니다.

`skills`도 비슷합니다.

같은 종류의 작업을 매번 새로 설명하지 않고, 미리 정리된 절차를 재사용할 수 있기 때문입니다.

## Custom instructions with AGENTS.md
Codex는 작업을 시작할 때 `AGENTS.md`를 읽습니다.

이 문서는 한 번에 하나만 있는 것이 아니라, 여러 층으로 쌓일 수 있습니다.

### 읽는 순서
1. Codex는 먼저 더 넓은 범위의 기본 지침을 봅니다.
2. 그다음 현재 프로젝트와 현재 폴더에 있는 `AGENTS.md`를 봅니다.
3. 더 가까운 폴더의 지침이 더 넓은 범위의 지침보다 우선합니다.

### 우리 작업공간에서의 예
아래 파일은 `AI 해봄` 예시 작업공간에 있는 파일입니다.

참가자가 새로 만든 개인 실습 폴더에는 처음부터 이 파일들이 없을 수 있습니다.

- 루트의 `AGENTS.md`는 전체 작업공간의 기본 규칙입니다.
- `raw/AGENTS.md`는 원본 자료를 다룰 때의 규칙입니다.

즉, Codex는 같은 프로젝트 안에서도 폴더에 따라 다른 지침을 읽을 수 있습니다.

### AI 해봄 작업공간 AGENTS.md에는 무엇이 들어 있나
`AI 해봄` 작업공간의 `AGENTS.md`에는 수업 자료를 만들기 위한 기본 운영 규칙이 미리 들어 있습니다.

초보자는 전체 내용을 외울 필요가 없습니다.

아래 정도만 이해하면 됩니다.

- 이 작업공간은 `AI 해봄` 동호회 자료를 만드는 곳입니다.
- 대상자는 대부분 초보자입니다.
- 설명자료는 한국어로 쉽고 짧게 씁니다.
- 원본 자료는 `raw/`에 두고 함부로 고치지 않습니다.
- 배부할 결과물은 `Output/`에 둡니다.

즉, 이 파일은 Codex에게 “이 공간에서는 이런 기준으로 작업해라”라고 알려주는 안내문입니다.

### 초보자가 기억할 점
- 먼저 큰 규칙을 보고, 그다음 세부 규칙을 봅니다.
- 더 가까운 폴더의 규칙이 더 중요할 수 있습니다.
- 그래서 작업할 폴더를 제대로 여는 것이 중요합니다.
- `AGENTS.md`는 사람이 직접 작성하는 파일이므로, 필요할 때 새로 만들거나 고쳐 쓸 수 있습니다.
- 파일이 없다면 Codex가 자동으로 만들어 둔 것이 아니라, 아직 사람이 만들지 않은 상태라고 보면 됩니다.

### 가장 쉬운 첫 AGENTS.md 예시
처음에는 업무 규칙보다 바로 눈에 보이는 규칙이 좋습니다.

예를 들어 아래처럼 말투 규칙을 넣을 수 있습니다.

```md
# AGENTS.md

- 항상 한국어로 대답한다.
- 초보자도 이해할 수 있게 쉽게 설명한다.
- 답변 마지막에 "오늘도 해봄!"을 붙인다.
```

이 예시는 실제 업무 규칙이라기보다, `AGENTS.md`에 적은 내용을 Codex가 읽고 따르는지 확인하기 위한 연습입니다.

확인 요청은 이렇게 할 수 있습니다.

```text
AGENTS.md에 적힌 규칙을 읽고, AGENTS.md가 무엇인지 한 문장으로 설명해줘.
```

기대하는 결과는 아래처럼 마지막 문장이 붙는 것입니다.

```text
AGENTS.md는 Codex가 작업할 때 참고하는 규칙 문서입니다.

오늘도 해봄!
```

이후 실제 업무에서는 말투보다 파일 저장 위치, 원본 보호, 설명 방식 같은 작업 기준을 적으면 됩니다.

## Agent Skills
`skills`는 반복해서 쓰는 작업 절차입니다.

쉽게 말하면, 자주 하는 일을 위한 작업 설명서나 플레이북에 가깝습니다.

### 왜 필요한가
- 매번 같은 절차를 다시 설명하지 않아도 됩니다.
- Codex가 더 일관된 방식으로 작업할 수 있습니다.
- 복잡한 작업을 작은 역할로 나누기 좋습니다.

### 언제 떠올리면 좋은가
- 같은 종류의 작업을 자주 할 때
- 절차가 정해져 있을 때
- 문서나 코드 작업을 반복해서 할 때

### 우리 수준에서의 해석
- 지금은 skill을 완벽히 만들 필요는 없습니다.
- 먼저 “이런 반복 작업은 따로 묶을 수 있구나”를 이해하면 충분합니다.
- 나중에 필요해지면 실제 skill로 분리할 수 있습니다.

### 예시: 사진 기반 스케치 프로필 카드
예를 들어 `profile-sketch-card`라는 skill을 만들 수 있습니다.

이 skill은 참가자 사진과 가벼운 학습 키워드를 받아서, 같은 스케치 노트 스타일의 프로필 카드를 만드는 절차입니다.

여기서 중요한 것은 그림 자체가 아닙니다.

중요한 것은 “사진이 바뀌어도 같은 방식으로 요청하고, 비슷한 형식의 결과를 반복해서 얻을 수 있다”는 점입니다.

예를 들어 첫 번째 사람은 `작은 자동화 도전자`, 두 번째 사람은 `키보드 항해자`, 세 번째 사람은 `회의록 정리 장인` 같은 재미용 키워드를 붙일 수 있습니다.

다만 실제 사람 사진을 사용할 때는 주의해야 합니다.

- 당사자가 사용을 허락한 사진만 사용합니다.
- AI가 성격, 능력, 건강, 나이, 외모, 퍼스널컬러를 판단하게 하지 않습니다.
- 키워드는 분석 결과가 아니라 재미용 학습 태그라고 설명합니다.

이 예시는 “skill은 반복 가능한 작업 절차”라는 점을 눈으로 보여주기 위한 예시입니다.

## 오늘의 진행 순서
1. `AI 해봄` 예시 작업공간의 루트 `AGENTS.md`를 연다.
2. `AI 해봄` 예시 작업공간의 `raw/AGENTS.md`와 비교해 본다.
3. 참가자 개인 실습 폴더에는 처음에 이 파일들이 없을 수 있음을 확인한다.
4. 말투가 바로 바뀌는 아주 쉬운 `AGENTS.md` 생성 예시를 본다.
5. Codex가 어떤 지침을 먼저 읽는지 설명을 듣는다.
6. `skills`가 무엇인지 예시로 이해한다.
7. `profile-sketch-card` 예시로 같은 스타일이 반복되는 모습을 본다.
8. `skills`가 어떻게 적용되는지 본다.
9. 결과를 확인하고, 다음 작업으로 이어가는 흐름을 본다.

## 비교해서 볼 포인트
- 루트 `AGENTS.md`는 전체 기본 규칙을 담는다.
- 하위 폴더 `AGENTS.md`는 그 폴더에서만 필요한 추가 규칙을 담는다.
- `skills`는 규칙보다 더 구체적인 반복 작업 절차에 가깝다.

## 시연 예시
- `AI 해봄 예시 작업공간에서 어떤 AGENTS.md 파일들이 적용되는지 한 번에 설명해줘.`
- `AI 해봄 예시 작업공간의 루트 AGENTS.md와 raw/AGENTS.md의 역할 차이를 초보자 기준으로 말해줘.`
- `현재 폴더에 AGENTS.md를 만들고, 항상 한국어로 대답한다, 쉽게 설명한다, 답변 마지막에 "오늘도 해봄!"을 붙인다는 규칙을 넣어줘.`
- `AGENTS.md에 적힌 규칙을 읽고, AGENTS.md가 무엇인지 한 문장으로 설명해줘.`
- `skills가 무엇인지, 왜 반복 작업에 도움이 되는지 한 문단으로 설명해줘.`
- `profile-sketch-card 스킬을 사용해서 사진과 재미용 학습 키워드로 같은 스케치 노트 스타일의 프로필 카드 예시를 만들어줘. 단, 성격이나 외모 평가는 하지 마.`

## 자주 막히는 지점
- 파일이 많아지면 어떤 것이 먼저 적용되는지 헷갈리는 경우
- `AGENTS.md`가 자동 생성된다고 오해하는 경우
- 새 실습 폴더에도 당연히 `AGENTS.md`가 있을 것이라고 생각하는 경우
- `AGENTS.md`와 `skills`를 같은 종류의 파일로 생각하는 경우
- 원본 규칙과 하위 폴더 규칙의 차이를 놓치는 경우
- 문서가 많다고 해서 다 한 번에 외우려는 경우

## 각자 할 일
- `AI 해봄` 예시 작업공간의 루트 `AGENTS.md`를 다시 읽는다.
- `AI 해봄` 예시 작업공간의 `raw/AGENTS.md`와 비교한다.
- 두 문서가 왜 다르게 쓰였는지 이해한다.
- 내 개인 실습 폴더에 `AGENTS.md`가 없다면 새로 만들 수 있다는 점을 기억한다.
- 말투가 바로 바뀌는 쉬운 `AGENTS.md` 규칙을 직접 써 본다.
- 익숙해지면 내 업무 폴더에 필요한 작업 규칙 한 줄을 생각해 본다.
- `skills`를 “반복 작업을 위한 절차”로 다시 설명해 본다.

## 다음 회차 예고
다음 회차에서는 플랜모드로 큰 요청을 작은 계획으로 나누는 법을 익힙니다.

바로 실행하지 않고, AI가 되묻는 질문에 답하면서 입력, 작업, 출력, 확인 기준을 정리합니다.

## 마무리
이번 회차의 핵심은 하나입니다.

`AGENTS.md`는 사람이 직접 쓰는 작업 기준, `skills`는 반복 절차입니다.

이 두 개념을 알면 Codex가 왜 이렇게 움직이는지 훨씬 잘 이해할 수 있습니다.
