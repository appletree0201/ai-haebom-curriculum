# 7회차

## 오늘의 목표
- Obsidian이 Markdown 기반 노트 도구라는 점을 이해한다.
- LLM Wiki가 원본 자료를 AI가 정리한 위키로 쌓아 가는 방식이라는 점을 안다.
- `raw/`, `wiki/`, `Output/` 구조를 다시 이해한다.
- 회의자료 같은 반복 문서를 지식으로 축적하는 활용 사례를 본다.

## 먼저 알아둘 말
오늘은 Obsidian 기능을 모두 배우는 시간이 아닙니다.

자료를 그냥 파일로 쌓아 두는 것과, AI가 정리한 위키로 축적하는 것의 차이를 보는 시간입니다.

실제 내부 회의자료는 공개 자료에 넣지 않습니다.

## 왜 이걸 배우는가
반복 회의자료, 보고자료, 공지자료는 시간이 지나면 다시 찾기 어렵습니다.

LLM Wiki 방식은 원본을 보관하고, AI가 요약과 연결 관계를 정리해 위키로 쌓는 방식입니다.

이렇게 하면 나중에 특정 주제, 결정사항, 반복되는 업무 이슈를 다시 찾기 쉬워집니다.

## 핵심 개념 1: Obsidian
Obsidian은 Markdown 파일을 노트처럼 보고 연결할 수 있는 도구입니다.

파일은 그냥 `.md` 파일이지만, 링크와 그래프를 통해 지식 구조를 볼 수 있습니다.

## 핵심 개념 2: LLM Wiki
LLM Wiki는 AI가 원본 자료를 읽고 정리한 지속형 위키입니다.

단순히 파일을 검색하는 것이 아니라, 내용을 요약하고, 관련 페이지를 만들고, 서로 연결합니다.

## 세 가지 폴더
| 폴더 | 역할 |
|---|---|
| `raw/` | 원본 자료 보관 |
| `wiki/` | AI가 정리한 위키 |
| `Output/` | 공유 가능한 결과물 |

원본은 함부로 수정하지 않습니다.

정리와 활용은 `wiki/`와 `Output/`에서 합니다.

## 활용 예시
매주 임원회의 자료가 있다면 아래처럼 활용할 수 있습니다.

- 회의자료 원본을 `raw/`에 보관합니다.
- AI가 주요 안건과 반복 이슈를 요약합니다.
- 관련 주제별 위키 페이지를 갱신합니다.
- 자동화 후보나 후속 조치 후보를 뽑습니다.
- 나중에 같은 주제를 다시 검색합니다.

## 함께 확인할 포인트
- 원본과 정리본은 역할이 다릅니다.
- 위키는 한 번 만들고 끝나는 문서가 아니라 계속 갱신되는 지식 구조입니다.
- 내부자료는 공개 자료에 넣지 않습니다.
- 자동화 후보는 반복 회의자료 안에서도 찾을 수 있습니다.

## 각자 해보기
- 내 업무에서 반복해서 쌓이는 자료를 하나 떠올립니다.
- 그 자료를 원본으로 보관할 위치를 생각합니다.
- AI가 요약해 주면 도움이 될 항목을 적습니다.
- 나중에 다시 찾고 싶은 주제를 적습니다.
- 내부자료와 공개 가능한 자료를 구분해 봅니다.

## 다음 회차 예고
다음 회차에서는 각자가 진행 중인 업무자동화 과제를 공유하고, 지원이나 협업이 필요한 부분을 연결합니다.

## 마무리
7회차의 핵심은 자료를 그냥 보관하지 않고 지식으로 축적하는 관점입니다.

LLM Wiki는 회의자료, 보고자료, 업무 메모를 나중에 다시 쓸 수 있게 만드는 방식입니다.
