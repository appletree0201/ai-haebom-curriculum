# 7회차

## 오늘의 주제
오늘은 Obsidian을 소개하고, LLM Wiki 방식으로 회의자료를 지식으로 쌓는 흐름을 봅니다.

실제 시연은 AI 해봄 운영자가 별도 노트북에서 준비한 임원 티타임 회의자료로 진행합니다.

배포 자료에는 실제 내부 회의자료 내용은 넣지 않습니다.

## 오늘의 목표
- Obsidian이 무엇인지 이해한다.
- LLM Wiki가 일반 요약과 어떻게 다른지 이해한다.
- `raw/`, `wiki/`, `Output/` 구조를 다시 본다.
- 회의자료 PDF가 위키로 정리되는 흐름을 본다.
- 회의자료에서 안건, 부서, 후속조치, 자동화 후보가 어떻게 분리되는지 이해한다.
- 내부자료를 다룰 때 주의할 점을 안다.

## 먼저 알아둘 말
오늘은 Obsidian의 모든 기능을 배우는 시간이 아닙니다.

오늘은 Obsidian을 `자료를 보는 창`으로 이해합니다.

그리고 Codex는 `자료를 읽고 위키를 정리하는 작업자`로 이해합니다.

```text
Obsidian = 정리된 노트를 보고 연결을 따라가는 도구
Codex = 원본 자료를 읽고 위키를 정리하는 도구
LLM Wiki = 원본 자료를 계속 쌓아 가며 연결된 지식으로 만드는 방식
```

## 일반 요약과 LLM Wiki의 차이
일반 요약은 보통 한 번의 답변으로 끝납니다.

```text
이 회의자료를 요약해줘.
```

LLM Wiki는 요약에서 끝나지 않습니다.

회의자료에서 나온 안건, 부서, 후속조치, 자동화 후보를 나누고, 기존 위키와 연결합니다.

```text
회의자료 PDF
-> 회의자료 요약
-> 부서별 안건
-> 주요 일정
-> 후속조치
-> 반복 현안
-> 자동화 후보
-> index.md / log.md 갱신
```

핵심 차이는 `누적`입니다.

매번 새로 요약하는 것이 아니라, 자료가 들어올수록 위키가 점점 풍부해집니다.

## 세 가지 폴더 다시 보기
LLM Wiki는 세 층으로 이해하면 됩니다.

```text
raw/    = 원본 자료 보관
wiki/   = AI가 정리한 지식 위키
Output/ = 배포하거나 공유할 결과물
```

오늘 시연에서 회의자료 PDF는 `raw/`에 들어갑니다.

Codex는 원본을 직접 수정하지 않고 읽기만 합니다.

정리된 결과는 `wiki/`에 만들어집니다.

## 임원회의 자료로 할 수 있는 일
임원회의 자료는 LLM Wiki 시연에 적합합니다.

이유는 매주 쌓이고, 부서별 안건과 후속조치가 반복되기 때문입니다.

LLM Wiki로 할 수 있는 일은 아래와 같습니다.

- 회의자료 요약
- 부서별 안건 분류
- 주요 일정 정리
- 결정사항 또는 후속조치 후보 추출
- 반복 현안 추적
- 자동화 후보 발굴
- 다음 회의에서 확인할 질문 만들기

## 시연에서 볼 흐름
시연 흐름은 아래와 같습니다.

```text
1. raw/meetings/ 에 회의자료 PDF를 넣는다.
2. Codex에게 LLM Wiki 방식으로 반영해 달라고 요청한다.
3. wiki/meetings/ 에 회의자료 요약 페이지가 생긴다.
4. wiki/departments/ 에 부서별 안건 페이지가 생긴다.
5. wiki/trackers/ 에 후속조치 또는 자동화 후보 페이지가 생긴다.
6. wiki/index.md 가 갱신된다.
7. wiki/log.md 에 처리 이력이 남는다.
8. Obsidian에서 링크가 연결된 모습을 본다.
```

## 시연 요청 예시
Codex에게는 아래처럼 요청할 수 있습니다.

```text
raw/meetings/ 폴더에 새로 넣은 회의자료 PDF를 LLM Wiki 방식으로 반영해줘.

회의자료 요약, 부서별 안건, 후속조치 후보, 자동화 후보를 분리해서 정리하고,
관련 위키 페이지를 만들거나 갱신해줘.

wiki/index.md와 wiki/log.md도 함께 갱신해줘.

원본 PDF는 수정하지 마.
```

## 생성될 수 있는 위키 페이지 예시
실제 이름은 자료에 따라 달라질 수 있습니다.

예시는 아래와 같습니다.

```text
wiki/meetings/2026-05-18-executive-teatime.md
wiki/departments/경력관리본부.md
wiki/departments/미래전략실.md
wiki/topics/민원-처리-개선.md
wiki/topics/회원-복지.md
wiki/trackers/후속조치.md
wiki/trackers/자동화-후보.md
```

## 활용 질문 예시
위키로 정리된 뒤에는 이런 질문을 할 수 있습니다.

```text
이번 회의자료에서 부서별 주요 안건을 정리해줘.
```

```text
후속조치로 보이는 항목만 따로 뽑아줘.
```

```text
자동화 후보가 될 만한 반복 업무를 찾아줘.
```

```text
지난 회의자료와 비교했을 때 반복되는 안건을 알려줘.
```

```text
이번 회의자료를 바탕으로 다음 회의에서 확인할 질문을 만들어줘.
```

## 자동화 후보로 이어지는 예시
회의자료에서 반복해서 나오는 표현은 자동화 후보가 될 수 있습니다.

예시는 아래와 같습니다.

- 반복 문의 유형 분류
- 회의자료에서 후속조치 자동 추출
- 부서별 안건 자동 분류
- 일정과 마감일 목록화
- 지난 회의와 이번 회의의 반복 안건 비교

이런 후보는 5회차에서 만든 자동화 과제 카드 형식으로 다시 정리할 수 있습니다.

## 내부자료 취급 주의사항
오늘 가장 중요한 주의사항입니다.

- 실제 회의자료는 외부 도구에 무단 업로드하지 않는다.
- 민감한 이름, 수치, 내부 의사결정 내용은 배포 자료에 넣지 않는다.
- 시연은 승인된 환경과 로컬 파일 기준으로 진행한다.
- 결과물은 AI가 만든 초안이므로 담당자가 확인한다.
- 원본 PDF는 `raw/`에 보관하고 직접 수정하지 않는다.

## 오늘의 진행 순서
1. 6회차 Git 복습: 기록을 남기는 이유를 떠올린다.
2. Obsidian을 자료를 보는 창으로 소개한다.
3. LLM Wiki의 `raw/`, `wiki/`, `Output/` 구조를 다시 본다.
4. 회의자료 PDF가 들어오면 어떤 일이 생기는지 설명한다.
5. 별도 노트북에서 실제 회의자료 PDF 반영 시연을 본다.
6. 생성된 위키 페이지 예시를 확인한다.
7. Obsidian에서 링크와 연결 구조를 본다.
8. 회의자료에서 자동화 후보를 뽑는 질문 예시를 본다.
9. 내부자료 취급 주의사항을 정리한다.

## 집에서 할 일
내 업무에서 계속 쌓이는 자료를 하나 골라 봅니다.

예시는 아래와 같습니다.

- 주간 회의자료
- 업무보고 자료
- 민원 또는 문의 목록
- 교육 운영 기록
- 점검 결과 보고서
- 반복 안내문

아래 4칸으로 적습니다.

```text
자료 이름:
얼마나 자주 쌓이는가:
나중에 다시 찾고 싶은 정보:
자동으로 정리되면 좋은 항목:
```

그리고 다음 8회차 전에 `지원·협업 요청 카드`를 작성해 옵니다.

8회차는 완성품 발표가 아닙니다.

각자 또는 각 부서에서 진행 중인 업무자동화 과제가 어디까지 왔는지, 어떤 도움이 필요한지 공유하는 시간입니다.

아래 4칸을 미리 채워 옵니다.

```text
과제 이름:
현재 단계:
도움이 필요한 부분:
함께하면 좋은 사람/부서:
```

## 다음 회차 예고
다음 8회차는 `업무자동화 진행 상황 공유와 지원·협업 연결` 시간입니다.

새로운 도구를 배우는 시간이 아닙니다.

각자 작성해 온 협업카드를 바탕으로 현재 상태를 공유하고, 동호회 차원에서 도울 수 있는 내용을 모읍니다.

목표는 완성도 평가가 아니라 다음 행동을 정하는 것입니다.

## 마무리
7회차의 핵심은 Obsidian을 예쁜 메모장으로 보는 것이 아닙니다.

회의자료처럼 반복해서 쌓이는 자료를 AI와 함께 정리하면, 결정사항, 후속조치, 반복 현안, 자동화 후보를 계속 추적할 수 있습니다.
