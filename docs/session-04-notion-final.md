# 4회차

## 오늘의 목표
- 실제 업무자동화가 어떤 흐름으로 만들어지는지 본다.
- 홈페이지 문의 자동 분류와 답변 초안 생성 사례를 이해한다.
- 자동화 결과를 그대로 믿지 않고 사람이 확인해야 한다는 점을 안다.
- 내 업무에도 비슷한 구조가 있는지 생각해 본다.

## 먼저 알아둘 말
오늘은 회원들이 만든 과제를 발표하는 시간이 아닙니다.

우리 부서에서 구현 중인 업무자동화 작업본을 보고 인사이트를 얻는 시간입니다.

완성품 평가가 아니라 “업무가 자동화로 바뀌는 흐름”을 보는 것이 목적입니다.

## 사례 개요
대상 업무는 홈페이지로 들어오는 질문을 읽고, 유형을 분류한 뒤, 답변 초안을 만드는 자동화입니다.

사람이 매번 처음부터 판단하고 쓰던 일을 아래처럼 나눕니다.

1. 질문 내용을 읽습니다.
2. 문의 유형을 분류합니다.
3. 유형에 맞는 답변 초안을 만듭니다.
4. 사람이 답변을 확인하고 수정합니다.

## 예시
질문:

```text
정밀안전진단 보수교육이 승급교육으로 인정이 될까요?
```

자동 분류:

```text
승급교육 대상·대체인정
```

답변 초안:

```text
다른 법령에 따른 교육·훈련을 이수하신 경우에는 관련 기준에 따라 일부 인정 여부를 검토할 수 있습니다.
정확한 인정 여부는 이수하신 교육의 법적 근거, 교육 시간, 교육 내용이 승급교육 기준에 부합하는지 확인한 뒤 판단됩니다.
관련 증빙자료를 준비해 담당 부서에 문의해 주세요.
```

## 자동화 구조
이 사례는 아래 네 단계로 볼 수 있습니다.

| 단계 | 의미 |
|---|---|
| 입력 | 홈페이지 질문 |
| 분류 | 문의 유형 판단 |
| 생성 | 답변 초안 작성 |
| 확인 | 담당자가 검토하고 수정 |

자동화가 모든 판단을 대신하는 것이 아닙니다.

초안을 빠르게 만들고, 사람은 더 중요한 확인과 판단에 집중하게 하는 구조입니다.

## 왜 이 사례를 보는가
업무자동화는 거창한 시스템부터 시작하지 않아도 됩니다.

반복해서 들어오는 질문, 반복해서 쓰는 답변, 반복해서 분류하는 자료가 있다면 자동화 후보가 될 수 있습니다.

오늘 사례를 보며 각자 업무에서 비슷한 반복 구조를 찾아보면 됩니다.

## 함께 확인할 포인트
- 자동화는 입력, 작업, 출력, 확인으로 나눠 볼 수 있습니다.
- 답변 초안은 최종 답변이 아닙니다.
- 사람이 확인해야 할 기준을 반드시 남겨야 합니다.
- 반복되는 질문과 반복되는 답변은 좋은 자동화 후보입니다.

## 각자 해보기
- 우리 부서에서 반복해서 들어오는 질문을 하나 적습니다.
- 그 질문을 어떤 유형으로 나눌 수 있는지 적습니다.
- 자주 쓰는 답변 문장이 있는지 찾아봅니다.
- 사람이 반드시 확인해야 하는 기준을 적습니다.
- 자동화가 도와줄 부분과 사람이 판단할 부분을 나눠 봅니다.

## 마무리
4회차의 핵심은 자동화 결과물이 아니라 자동화 구조를 보는 것입니다.

입력, 분류, 초안, 확인의 흐름을 이해하면 내 업무에서도 자동화 후보를 찾기 쉬워집니다.
