# 4회차

## 오늘의 주제
실제 업무자동화 구현 사례를 봅니다.

사례는 `홈페이지 문의 자동 분류와 답변 초안 생성`입니다.

오늘은 회원 각자가 만든 것을 발표하는 시간이 아닙니다.

AI 해봄에서 실제로 만들고 있는 업무자동화 작업본을 보고, 자동화가 어떤 순서로 만들어지는지 이해하는 시간입니다.

## 오늘의 목표
- 실제 업무자동화가 어떤 문제에서 시작되는지 안다.
- 홈페이지 문의를 `분류`하고 `답변 초안`을 만드는 흐름을 본다.
- AI가 확정 답변을 하는 것이 아니라, 담당자가 검토할 초안을 만든다는 점을 이해한다.
- 3회차에서 배운 플랜모드가 실제 구현 과정에 어떻게 연결되는지 본다.
- 내 업무에서도 비슷하게 나눌 수 있는 반복 작업을 떠올린다.

## 먼저 알아둘 말
오늘 보는 자동화는 완성품 자랑이 아닙니다.

작업본을 보면서 아래 질문을 함께 생각하는 시간입니다.

```text
이 업무는 어떤 반복에서 시작했을까?
사람이 하던 판단은 무엇일까?
AI에게 맡길 수 있는 부분은 어디까지일까?
사람이 반드시 확인해야 하는 부분은 무엇일까?
```

업무자동화는 처음부터 거창하게 시작하지 않습니다.

반복해서 읽는 일, 반복해서 나누는 일, 반복해서 초안을 쓰는 일부터 시작합니다.

## 사례 업무
홈페이지에 질문이 들어옵니다.

담당자는 질문을 읽고 아래 일을 합니다.

1. 어떤 유형의 질문인지 판단한다.
2. 관련 기준이나 안내 문구를 떠올린다.
3. 답변 초안을 작성한다.
4. 최종 답변으로 보내도 되는지 확인한다.

이 중에서 오늘 자동화 사례는 1번과 3번을 중심으로 봅니다.

```text
질문 입력
-> 자동 분류
-> 답변 초안 생성
-> 담당자 확인
```

## 오늘 다루는 범위
오늘 다루는 범위는 아래 두 가지입니다.

- 문의 내용을 읽고 질문 유형을 분류한다.
- 분류 결과에 맞는 답변 초안을 만든다.

오늘 다루지 않는 범위도 분명히 합니다.

- 홈페이지에 자동으로 답변을 등록하지 않는다.
- 추천 메뉴를 자동으로 고르지 않는다.
- 법령 적용이나 인정 여부를 AI가 확정하지 않는다.
- 담당자 확인 없이 민원 답변을 완성하지 않는다.

## 대표 예시
질문입니다.

```text
정밀안전진단 보수교육이 승급교육으로 인정이 될까요
```

자동 분류 결과입니다.

```text
승급교육 대상·대체인정
```

답변 초안입니다.

```text
정밀안전진단 보수교육이 승급교육으로 인정되는지는 교육 종류, 이수 시기, 관련 법령, 제출 증빙자료에 따라 달라질 수 있습니다.

다른 법령에 따른 교육·훈련을 이수한 경우 일부 교육이 대체 인정될 수 있으나, 최종 인정 여부는 담당 부서의 확인이 필요합니다.

교육명, 이수기관, 이수일자, 수료증 등 관련 자료를 첨부하여 문의해 주시면 확인 후 안내드리겠습니다.
```

이 예시에서 중요한 점은 `인정됩니다` 또는 `인정되지 않습니다`라고 확정하지 않는 것입니다.

AI는 초안을 만들고, 담당자는 기준과 증빙을 확인합니다.

## 왜 이 사례가 좋은가
이 사례는 초보자가 업무자동화를 이해하기 좋습니다.

이유는 아래와 같습니다.

- 질문이 자연어라서 실제 업무와 가깝다.
- 분류 결과가 눈에 바로 보인다.
- 답변 초안이 있어 자동화 효과를 느끼기 쉽다.
- 하지만 최종 판단은 사람이 해야 한다는 경계도 분명하다.

자동화는 사람을 빼는 것이 아닙니다.

반복되는 초안 작업을 줄이고, 사람이 확인해야 할 일에 집중하게 만드는 것입니다.

## 구현 흐름을 작게 나누기
이 자동화도 처음에는 큰 요청으로 시작할 수 있습니다.

```text
홈페이지 문의에 자동으로 답변하게 해줘.
```

하지만 이 요청은 너무 큽니다.

3회차에서 배운 것처럼 작은 단계로 나눠야 합니다.

```text
1. 문의 예시를 모은다.
2. 자주 나오는 문의 유형을 정한다.
3. 문의를 유형별로 분류하는 기준을 만든다.
4. 유형별 답변 초안 작성 기준을 만든다.
5. 샘플 문의로 분류 결과를 확인한다.
6. 답변 초안이 위험하게 확정 표현을 쓰는지 확인한다.
7. 담당자가 최종 수정할 수 있게 결과를 보여준다.
```

이렇게 나누면 Codex에게 요청하기 쉬워집니다.

## 입력, 작업, 출력, 확인으로 보기
오늘 사례도 4칸 공식으로 볼 수 있습니다.

```text
입력: 홈페이지 문의 내용
작업: 문의 유형 분류와 답변 초안 작성
출력: 분류명, 답변 초안
확인: 분류가 맞는지, 초안이 확정 답변처럼 보이지 않는지
```

이 네 칸이 정리되어야 자동화 결과를 확인할 수 있습니다.

## AI가 하는 일과 사람이 하는 일
AI가 할 수 있는 일입니다.

- 문의 내용을 읽는다.
- 비슷한 유형을 고른다.
- 답변 초안을 만든다.
- 확인해야 할 정보를 문장에 포함한다.

사람이 해야 하는 일입니다.

- 분류가 맞는지 확인한다.
- 법령, 규정, 내부 기준을 확인한다.
- 인정 여부처럼 중요한 판단을 확정한다.
- 실제 발송 전 표현을 수정한다.

이 구분이 중요합니다.

AI가 만든 초안은 편리하지만, 책임 있는 답변은 사람이 확인해야 합니다.

## 오늘의 진행 순서
1. 홈페이지 문의 업무가 왜 반복되는지 본다.
2. 기존 수작업 흐름을 확인한다.
3. 자동화 후 흐름을 본다.
4. 대표 질문을 입력한다.
5. 자동 분류 결과를 확인한다.
6. 답변 초안을 확인한다.
7. AI가 한 일과 사람이 확인할 일을 나눈다.
8. 내 업무에서 비슷한 반복 작업을 떠올린다.

## 토론 질문
- 우리 업무에서 반복해서 읽고 분류하는 자료는 무엇인가?
- 답변 초안이나 안내 문구를 반복해서 쓰는 일이 있는가?
- AI가 초안을 만들 수 있지만 사람이 꼭 확인해야 하는 부분은 무엇인가?
- 자동화 결과를 믿기 전에 무엇을 확인해야 하는가?

## 집에서 할 일
다음 5회차 전까지 각 부서에서 자동화하면 좋을 반복 업무를 하나 이상 생각해 옵니다.

처음부터 완벽한 아이디어일 필요는 없습니다.

아래 질문에 맞춰 짧게 적어 오면 됩니다.

```text
1. 반복해서 하는 일인가?
2. 사람이 매번 읽고 판단하는 일인가?
3. 비슷한 문서나 답변을 자주 만드는 일인가?
4. 엑셀, 파일, 문의, 신청서처럼 자료가 들어오는 일인가?
5. 결과가 맞는지 사람이 확인할 수 있는 일인가?
```

예시는 아래와 같습니다.

- 문의 분류
- 신청서 검토
- 자료 접수 확인
- 반복 안내 문구 작성
- 파일명이나 제목 기준 분류
- 엑셀 명단 요약
- 회의 메모 정리

찾은 후보를 아래 4칸으로 간단히 적어 옵니다.

```text
입력:
작업:
출력:
확인:
```

## 다음 회차 예고
다음 회차에서는 각 부서에서 생각해 온 자동화 후보를 공유합니다.

그리고 Markdown으로 `부서별 자동화 과제 카드`를 작성합니다.

5회차에서 처음 아이디어를 떠올리면 시간이 부족합니다.

그래서 4회차 이후에는 각 부서에서 자동화하면 좋을 반복 업무를 하나 이상 생각해 오는 것이 중요합니다.

## 마무리
4회차의 핵심은 실제 업무자동화가 만들어지는 방식을 보는 것입니다.

자동화는 한 번에 완성되지 않습니다.

반복 업무를 찾고, 작은 단계로 나누고, 결과를 확인하면서 조금씩 만듭니다.

오늘 본 사례처럼 `분류`와 `초안 작성`만 자동화해도 업무 부담을 줄일 수 있습니다.
